## 坑：my_app 接口「瞬时无响应」≠ 页面坏了（15:06–15:13 实测）

**现象**：e2e 直开 `/myapp/?page=repeat_site_down` 时页面全 0（4 个 Statistic 都是 0、图表 Empty、
Region 下拉空），第一反应像"新页面有 bug"。同时 `curl 127.0.0.1:7038/api/repeat-site-down/overview`
HTTP 000、90s / 35s 超时。

**关键证据**：
- **后端 access log 里那段时间完全没有该接口的记录** —— 说明请求根本没进到处理逻辑，
  不是接口算错、也不是页面渲染错（uvicorn 是响应后才写日志，排队中的请求不落日志）
- 同期的 `filters` 与 `tasks/running` 都 200，其他客户端（192.168.100.26）的
  `realtime-proxy/status`、`vmax-cxo-dashboard/*` 轮询也在正常处理
- PG 侧完全空闲：`pg_stat_activity` 只有 5 个连接、无长查询；
  `EXPLAIN` 显示该 SQL 计划健康（Bitmap Index Scan + `u_eflow_site` Index Scan + Memoize）
- 8 分钟后**自愈**；连续压测 8 次全部 200、稳定 0.40–0.50s

**结论**：后端并发容量问题（sync 端点跑在 anyio 线程池，被其他客户端的密集轮询占满时新请求排队），
**不是这个页面特有的、也不是我改门户引起的**。以后再遇到"页面全 0"，先 grep 后端日志看请求有没有落盘。
