## /v3/smc_portal/ 的 CCH + OSS Portal Login 布局与「CCH 加载不出来」

- 需求：CCH 与 OSS Portal Login 放同一行、CCH 在左；并修复 CCH 看起来加载不出来。
- 根因（无头 Chrome 实测）：smc 在 report 域一行未勾 → `renderEmailSection()` 把 #emailSlot 设 hidden，
  `.qarow` 这一行失去确定高度；`.oss-slot` 固定 `--oss-h`(430px)、`.cch-slot` 的 `flex:1` 无可分配高度，
  `.qarow .canvas { min-height:0 }` 又把画布压到 0，而 iframe 是 absolute 不参与流式高度 →
  cchCanvas 2px / iframe 0px。nginx 访问日志里 `/myapp/?page=vmax_user_query&embed=1&lang=en` 返回 304，
  说明 iframe 其实已加载，只是容器 0 高，不是地址或鉴权问题。
- 修法：在 `scripts/sync_team_assets.py` 的 `CSS_TEAM_SUFFIX` 追加团队专有规则（并重跑同步生成
  `v3/team_portal/assets/olbr.css`）：
  - `.qarow:has(> .email-slot:is([hidden],[data-tl-off],:empty))` 命中「Auto Report 隐藏」的团队（当前仅 smc）；
  - `.qarow-col` 改横向 flex、`height: var(--qarow-h)`，CCH 左 / OSS 右各一半；
  - OSS 卡片从 6 列降到 3 列（半行宽下 6 列太挤）；
  - 加 `:has(> :is(.cch-slot,.oss-slot):not([hidden]):not([data-tl-off]))` 守卫，
    避免 cxo（两块全隐藏）出现 860px 空白行；
  - <=900px 退回上下叠放并保留确定高度。
- 验证：无头 Chrome 量得 smc 宽屏 iframe 715×769（原 715×0）、CCH 在左；窄屏 693×323；
  cxo 两块全隐藏时该行 0 高；fo/bo/flm（Auto Report 可见）仍是原上下叠放。
  `sync_team_assets.py --check` / `patch_team_portal.py --check` / `check_scope_coverage.py` 均通过。
- 同时给 `v3/team_portal/index.html` 的 .qarow 注释补了这次改动说明；上游 `/v3/olbrportal/` 一行未动。

## 团队门户 Domain Dashboard 卡内条目改「flex 行流」（消掉右侧大片空白）

- 需求（用户原话）：「RAN 一行，放不下折两行，目前看一行还排不满，右边有大量空白，
  你有什么好的方案吗。检查其他团队门户，Domain Dashboard 也要一样的，
  团队门户页面保持一致。fo/bo/flm/smc/cxo」。
- 根因：原规则 `#views6 .v6-grid[data-n="1"] .v6-list { display:grid;
  grid-template-columns: repeat(auto-fit, minmax(280px,1fr)); }` —— CSS Grid 的**轨道数按整张列表宽度
  一次性算死**（1484px → 5 条 ~289px 轨道），与「某个专业域有几条」无关。RAN 占满 5 条轨道后，
  auto-fit 的空轨道永不塌陷，MW / OCS 只有 2 条却仍只占 1~2 号轨道，右侧空 ~870px。
  **不是「排不满」，是「轨道被别的组占了」。**
- 修法：在 `scripts/sync_team_assets.py` 的 `CSS_TEAM_SUFFIX` 里把那条 auto-fit 网格换成
  **flex 行流**（对所有 `data-n` 生效，不再只限单列）：
  - `.v6-list { display:flex; flex-flow:row wrap; gap:calc(4px*var(--v6-k)); align-content:start; }`
  - `.v6-seg-h` / `.v6-empty { flex: 0 0 100%; }` → 段头独占整行，每个专业域从新行开始
  - `.v6-row { flex: 1 1 280px; min-width:0; }` → **同一行内条数少的那组也被拉伸吃满整行**
  - `.v6-more { flex: 0 0 auto; align-self:center; }` → 展开按钮不独占整行
- 效果：bo 的 MW 两组各占半行（736px + 736px），右侧 0 空白；RAN 五条仍排满一行、放不下折两行。
  fo / cxo（单列平铺 4 条）4 × 365px 排满；flm（双列）每列 2 条 × 359px 排满。
  smc 没有 Domain Dashboard（scope-map.json 未勾任何视图列 → viewGroups() 为空 → 整块隐藏）。
- ⚠️ **DOM 结构不能动**：段头与条目必须仍是 `.v6-list` 的直接子元素 —— `team-layout.js`
  的拖拽排序按「`.v6-list > .v6-row`」取键与重排，加包装层就取不到键、排序失效。故用 CSS 解决。
- ⚠️ 上游 `/v3/olbrportal/` 一行未改（这条规则只在 `CSS_TEAM_SUFFIX` 里，只进 team_portal 生成物）。
  上游主门户六列窄卡本来就是竖排设计（实测 flex-direction: column），不适用。
- 验证：`sync_team_assets.py --check` / `check-team-scope.mjs` / `npm run lint` /
  `check-doc-consistency.mjs`（PASS=6 FAIL=0）/ `agent-done-check.mjs --full` 全绿；
  五个门户均用 CDP 实测坐标（改前改后对比写在 `docs/architecture.md` 九之十八）。
