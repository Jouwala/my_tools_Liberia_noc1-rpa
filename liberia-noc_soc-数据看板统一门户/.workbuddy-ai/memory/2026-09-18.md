## MsPortal「Quality Control 每小时更新」—— 先复核（本来就是每分钟），最终定稿「告警 5 分钟级 / 其余每小时」

用户原话：`http://localhost/MsPortal/` 页面的 Quality Control 内容「应该要每小时更新下，现在的数据呢是支持的」。
后续确认三轮：① 先在界面上把刷新节奏/数据时间写清楚；② 再把「每小时」真正落地；
③ 最后指出告警不能跟着一小时变旧 → **告警 5 分钟级 + 其余每小时**（当前线上形态）。

### 第一步：先量再改（没有直接照做）

- 无头 Chrome 实测（`TMP/probe_qc_refresh.cjs`）：进页面拉一次 `/api/portal-qc/summary`，
  之后**每 60 秒**自动拉一次，「更新于」自己从 01:27 走到 01:28，全程没点刷新
  → 当时「每小时更新」其实已经满足，而且更勤。
- 数据源节奏（`GET /api/tasks` 取 `current_cron`，注意实际值 ≠ `default_cron`）：
  `eflow_sync` 每小时 :00 起跑、耗时约 374s（≈ :06 跑完，TT/WO/CR/PMT 的源）；
  `eflow_active_alarm` 每 5 分钟（断站告警）；`sp_online_sync` 每小时 :35（SPMS）；
  `pg_to_sqlite_sync` 每小时 :45（本地兜底快照，耗时约 9.6 分钟）。
  → TT/WO/CR/PMT 一小时才变一次是**数据源**的节奏，不是页面没刷新。

### 第二步：界面呈现（用户选择「保持每分钟，把节奏写清楚」）

- `MsPortal/assets/portal.js` 标题栏由「更新于 HH:MM」变成
  「● 告警 5 分钟 · 其余每小时 :06 · 更新于 HH:MM:SS · 下次 MM:SS」，整条 span 的 `title` 写明两档节奏；
  心跳点复用现成的 `status-pulse-green`（取不到数据时变红且不脉冲）。
- 新增 `qcClock()` —— 顺手修掉一个**真 bug**：后端 `portal_qc.py` 的 `generated_at` 写死 `+08:00`，
  而页面右上角时钟用浏览器本地时区（本机 = 利比里亚 UTC），原样切字符串会出现
  「时钟 18:07」旁边写着「更新于 02:07」，看着像 8 小时前的旧数据 —— 这很可能就是
  「QC 好像没在更新」的错觉来源。现在按浏览器本地时区渲染，与页面时钟同一把尺子。

### 第三步：把「每小时」落地（第二轮）

- 节奏由「进页面起算每 60s」改为 **「每小时 :06:30 对齐」**：`qcNextDelay()` 按墙上的钟算下一个
  `:06:30`（源同步跑完之后 30s 余量），`setTimeout` 自链而不是 `setInterval`
  —— interval 只会从进页面那刻累加，:06 同步好的数据最多要再等 54 分钟才上屏。
- 倒计时改成定宽 `MM:SS`（`qcCountdown()`），避免标题栏每秒抖动。
- 保留三条「立即拿最新值」的通道：加载即拉、切回前台补拉（`visibilitychange`）、点「刷新」强制 `?refresh=1`。

### 第四步：分频刷新 —— 告警 5 分钟 / 其余每小时（第三轮，当前线上形态）

用户看完上一版直接指出：告警不能跟着一小时变旧。做法是**把两档拆开，各按自己的源节奏对齐**：

- 前端（`MsPortal/assets/portal.js`）
  - `qcNextDelay(stepMin, offsetSec)` 泛化成「N 分钟网格 + 偏移秒」，以**本地当天 0 点**为原点
    （不用 epoch：+05:30 这类半小时时区会整体偏 30 分钟）。两档常量：
    `QC_FULL_MIN=60 / QC_FULL_OFFSET=390`（每小时 :06:30）、`QC_ALARM_MIN=5 / QC_ALARM_OFFSET=30`
    （:00:30 / :05:30 …）。
  - 两条 `setTimeout` 自链：`qcLoopFull` → `fetchQcStats()`，`qcLoopAlarm` → `fetchQcAlarm()`。
    倒计时取两者中更近的那次（几乎总是告警档，≤5 分钟）。
  - `fetchQcAlarm()` 只覆盖 `state.qcAlarm` 一格，**绝不替换 `state.qcStats`**（否则其余五项被清空）；
    `qcMetric('alarm')` 优先返回它。失败时置 error 态而不是留旧值 —— 告警是这块最要紧的一格。
  - 标题栏「更新于」= 两档数据时间里较新的那份（`qcLatestStamp()`）；tooltip 里分别写明
    「告警最近 HH:MM:SS / 全量最近 HH:MM:SS」，因为分频后单看一个时间已经说不清全部。
- 后端（`D:\01_RPA\Task\my_app\backend\routers\portal_qc.py`）
  - `GET /api/portal-qc/summary?only=alarm`：**只算断站告警一项**（`_collect_alarm_only()`，
    口径与全量里的 alarm 逐字一致：同一段 SQL + 同一份 `_ALARM_WHERE`），
    缓存键与全量分开（`_alarm_cache`）—— 共用一份的话，每 5 分钟的告警请求会把全量那份
    60s 缓存顶掉，「其余每小时」就白做了。
  - 这条路径把「表正在被 DROP/CREATE 重建」也纳入重试（`_retry_missing_table(run, attempts=4, delay=0.8)`）：
    realtime_alarm 每 5 分钟被整表 replace 一次，全量路径里 `table_ok` 在重试之外抛，重建窗口内只能报错。
  - 改完重启：杀掉 7038 的 uvicorn 子进程即可，`backend_watchdog` 父进程 8 秒内自动拉起
    （实测 pid 47688 → 15268，`?only=alarm` 与全量都 200，两边 alarm 值一致）。

## Central Liberia Regional Topology 地图：滚轮缩放改成「先点地图」（21:50）

用户原话：「`http://localhost/MsPortal/` 的 Central Liberia Regional Topology 组件里面的地图，

### 改动落在 my_app 前端源码（门户只是内嵌方，portal.js 一行没动）

`D:\01_RPA\Task\my_app\frontend`（源码）→ `npm run build` → `D:/01_RPA/Task/_fe_dist`（nginx 直接 serve）：

| 文件 | 改法 |
| --- | --- |
| `src/components/MapWheelZoomOnClick.tsx`（新增） | `useMap()` + `isEmbeddedInPortal()`：内嵌态初始关滚轮缩放；`map.on('click')` 开、`map.on('blur')` 与容器 `mouseleave` 关；卸载时 `enable()` 还原 |

`isEmbeddedInPortal()` = `?mwembed=1`（门户 iframe 的 src 自带）或 `window.self !== window.top`。
判「是否内嵌」而不是「是否门户」，是因为 viewer.html 的看板预览弹窗也是 iframe 内嵌，同样不希望地图抢走外层滚动。

### 为什么这样能成立（关键前提，已实测）

`scrollWheelZoom.disable()` 后 Leaflet 不注册 wheel 监听、不 `preventDefault`，
**浏览器会把滚动链式传给父页面** —— 内嵌页 `html,body` 是 `overflow:hidden!important`，
所以滚动一路传到 MsPortal。实测每格滚轮门户页面 `scrollY` +120px，**没有出现「滚不动」的死区**。
若哪天链式传递不成立，兜底方案是内嵌页监听 wheel 后 `postMessage` 给门户代为滚动（本次不需要）。

### 证据（`TMP/verify_topo_wheel_click.cjs`，13 项全绿）

四个页签各自：A 未点击滚轮 → 门户 scrollY +120px 且地图 zoom 不变；B 点击后滚轮 → zoom +1、
**连续滚轮一直有效**（不用反复点）；C 指针移出再回来 → 已收回、滚轮不再缩放。
回归：独立打开 `/myapp/?page=gis` 时 `isTop=true`、`scrollWheelZoom.enabled()=true`、未点击直接滚轮 zoom 8→9。
另跑既有 `TMP/probe_map_tabs_framing.cjs`：取景数值与改动前基线一致（mwRealTime z7 fill.x 0.73；
三个 React 页 z8 —— GISMap 写死 zoom=8 是设计如此），**无取景回归**。

### 两个验证坑（下次直接绕开）

1. **CDP 的 `Input.dispatchMouseEvent` 只落在视口内**：地图 iframe 常在首屏之下（实测 top≈773px，
   点击点 y=1202 > 视口 1200），点在视口外时 click/wheel 全部石沉大海、事件探针一条不响。
   先把 `#secTopo` 摆到视口上部再算坐标（脚本里的 `placeMap()`）。
2. **React SPA 拿不到 Leaflet 实例**（容器上没有 `_leaflet_map`，react-leaflet v5 把 map 存在 context/hook 里）。
   判缩放别依赖实例：读瓦片 URL 里的 z（取出现次数最多的那个，动画期间新旧瓦片并存也稳）。
   要实例时：从容器的 `__reactFiber$*` **向上**走 `fiber.return` 并扫 `memoizedState` 钩子链（本次这样拿到了）。

### 关键判断（都踩过或差点踩）

1. **`--mp-mast-h` 必须挂在 `html` 上，不能挂 `.mp-mast`**：`.control-bar` 是顶栏的**兄弟**节点，
   挂在顶栏上的自定义属性它继承不到 —— 第一版 `top: var(--mp-mast-h)` 直接解析成 `auto`，
   滚动后工具条会钻到顶栏底下。实测抓到（`getComputedStyle(bar).top === 'auto'`）。
2. **顶栏盒子上的 background / border / box-shadow 用 `!important` 是故意的**：
   portal.css 有 `:root body > header`(0,1,2) 与 `html.dark body > header`(0,1,3) 两条同族规则，
   谁赢只看加载顺序，将来那边再改一次就可能翻盘。其余属性一律不用 `!important` ——
   视觉主体（渐变 / 地球 / 蓝光）全画在子层 `.mp-mast-bg` 上，子层天然盖住父元素 background。
3. **顶栏新文案不能用 `data-i18n`**：portal.js 的 `render()` 会把所有 `[data-i18n]` 按**它自己的**
   字典重写，字典里没有的 key 会被写成 key 本身（`t()` 兜底 `return key`），文案就没了。
   改用 `data-mp-i18n` / `data-mp-i18n-attr`，由 `masthead.js` 自己维护，靠 MutationObserver
   盯 `<html lang>` 跟着切。`#logoutBtn` 里那串仍用 `data-i18n="auth.logout"`（字典里有）。
4. **地球不能靠肉眼调**：参考图的球缘是逐行取最亮像素、再做最小二乘圆拟合量出来的 ——
   R ≈ 2.1×顶栏高、球心水平 ≈52.5%、球顶在顶栏上沿往下 ≈3%（参考图里球被顶栏上沿切掉一点）、
   底边可见弦宽 ≈3.5×顶栏高。前两版一版做成「亮球顶」、一版做小了，都是肉眼估的。
   球面要压得很暗，靠**球缘青光 + 贴边内辉光 + 点阵大陆**出效果。
5. **响应式断点必须用几何判定，不能看截图**：1340 以下开始收（英文副标题最长、先让位），
   1024 以下收登录用户名，768 以下 ZTE 字标与分隔线收起。验证脚本里加了
   「品牌区右缘 <= 控件区左缘」的断言 —— 第一版 1024/768 下标题直接压在语言按钮上，
   光看截图很容易漏。**站点入口（/uniplam/）窄屏收成纯图标但链接一直在**，那是它的主入口。
6. **达标率不另造口径**：取 `/api/portal-qc/summary` 的 `metrics.sla`，与 Quality Control 面板
   同源（线上实测两边都是 87.8%）。**绿点必须是真实探活结果** —— 2026-09-18 早些时候刚按需求
   删掉写死的「生产运行」绿点，这里不能借改版把它加回来：探活失败会变红且停跳。
   环境名也按真实 hostname 判定（localhost → 本机 / 其余 → 生产）。
7. **`masthead.js` 驱动门户状态一律走 DOM**（点 `#controlToggle`、写 `#searchInput` 并派发 `input`、
   点 `all` chip），不碰 portal.js 的内部变量 —— 绕过它会出现「看着展开了、`state.barOpen` 还是收起」。
8. **`assets/tailwind.css` 是编译产物**：新 markup 挂新 Tailwind 类不会生效，样式全部手写在
   `masthead.css`。
9. **后续（23:45 用户追加）「标题靠最左、右边文字靠最右」**：原因是宽屏下
   `.mp-mast-inner` 自带的 `max-width:1920px + margin:0 auto` 把整行居中了，2560px 上两边各留
   320px 空白。去掉它即可 —— 但**光删掉自己那条不够**：portal.css 的 `.control-toggle-row`
   也自带同样的 `max-width:1920px + margin:0 auto`，没有竞争声明时它照旧生效，
   工具条把手在 2560px 下仍被推到 344px 处（第一轮就漏了这条，几何断言抓出来）。
   所以 `.control-toggle-row` / `.control-inner` / `.edit-hint` 三处都要**显式**写
   `max-width:none; margin-left:0; margin-right:0`。页面正文区本身全宽，顶栏跟着全宽才对齐。
   保留 24px 内边距（18/12 随断点），要贴死到 0 再说。验证：`TMP/verify_live_flush.cjs`
   **21/21 通过**（2560/2200/1920 三个宽度：品牌区左缘、右侧控件右缘、把手左缘、右侧工具右缘
   全部 ≤24px，展开行 `left=0 / right=视口宽 / padding=24px`）；几何断言里已固化这四条。
