## B4 —— 匿名管理员出口【最高优先，不修则分数封顶】

**现象**：LAN 零凭据 `GET :7090/api/credentials` → 200 / 5,494 字节（凭据库）；`/api/auth/me` → `{"role":"admin"}`。

**根因**：`vite preview` 起的实例绑在 `0.0.0.0:7090`，它到后端的代理**对端是 `127.0.0.1`**，于是后端的"回环即管理员"信任被远程客户端复用。

**操作（在主机上，按序）**：
```powershell
# 1) 停掉 7090 上的 preview 进程
netstat -ano | findstr ":7090"        # 记下 PID
taskkill /PID <PID> /F

# 2) 商用实例：不再跑 vite preview；7090 由 nginx 直出静态产物（见 B1）
#    若必须保留 preview，则改绑回环：
npx vite preview --host 127.0.0.1 --port 7090

# 3) uvicorn 同步收回环
#    在 my_app 启动参数里把 --host 0.0.0.0 改为 --host 127.0.0.1
```

**验证**（期望 000/401，不再是 200）：
```bash
curl -s -m5 -o /dev/null -w "creds=%{http_code} " http://192.168.100.20:7090/api/credentials
curl -s -m5 -o /dev/null -w "catalog=%{http_code} " http://192.168.100.20:7090/api/portal-catalog
netstat -ano | grep -E "TCP.*:(7038|7090).*LISTEN"      # 期望仅 127.0.0.1
```
**回滚**：重启 preview 即可（原样）。

## B1 —— 生产脱 Vite dev server

**现象**：`/uniplam/` 响应含 `@vite/client` + `react-refresh`；登录/鉴权全在 dev 中间件里。

**做法**：新建 **`server/index.ts`（Express）**，把 `vite.config.ts` 里的两个插件中间件原样搬到生产服务器：
- `portalAuthPlugin(authStore, ['/api/auth','/uniplam/api/auth'])`
- `portal-default` 处理器（GET 已加鉴权门，POST 保持"管理员+回环"）

关键点：**`server/auth/index.ts` 已导出 `portalAuthPlugin` 与 `getAuthStore`**，可直接复用，**不需要改动鉴权逻辑本身**。

**步骤**：
1. 门户仓库新建 `server/index.ts`：`express()` + `express.static(dist)` + 挂载上面两个中间件 + 对 `/uniplam/*` 返回 `dist/index.html`（SPA 兜底）。
2. `package.json` 增：`"start": "node server/index.js"`（先 `tsc` 或 `tsx` 编出 `server/index.js`）。
3. 主机 `start_hidden.ps1:195` 的 `npm run dev` → 改 `npm start`；确保只有一个实例占 9267（加单实例锁）。

**验证**：
```bash
curl -s http://host/uniplam/ | grep -c "vite/client"    # 期望 0
curl -s -o /dev/null -w "%{http_code}" http://host/uniplam/   # 期望 200
```
**回滚**：改回 `npm run dev`。

## B2 —— 全站 TLS

**操作（主机 nginx）**：加 443 server + 证书，80 → 301 https：
```nginx
server {
  listen 443 ssl;
  server_name 192.168.100.20;
  ssl_certificate     /etc/nginx/certs/portal.crt;
  ssl_certificate_key /etc/nginx/certs/portal.key;
  # … 其余 location 同 80 站点
}
server { listen 80; server_name 192.168.100.20; return 301 https://$host$request_uri; }
```
**验证**：`curl -sk https://host/ -o /dev/null -w "%{http_code}"` → 200。
