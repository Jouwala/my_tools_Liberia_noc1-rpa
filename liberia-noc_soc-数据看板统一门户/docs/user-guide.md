# 06 user-guide.md —— 面向使用者的功能说明

> 基准日期：2026-09-22　|　项目根：`D:\01_RPA\liberia-noc_soc-数据看板统一门户`
> 面向：NOC/SOC 值班、网络优化工程师、管理层。**不需要懂代码。**

## 一、怎么打开

浏览器访问统一门户地址（部署在 nginx 的 `/uniplam/` 路径下，如 `http://192.168.100.19/uniplam/`）。

首次访问需要**登录**（账号由管理员分配）。忘记密码请联系管理员重置。

## 二、找到你要的看板

### 三种视图，按场景选

| 视图 | 什么时候用 | 长什么样 |
| --- | --- | --- |
| **卡片网格** | 日常找单个看板 | 大卡片、带描述，一屏看十几个 |
| **高密清单** | 你已经很熟，只想快点进去 | 一行一条，一屏看很多 |
| **业务分类矩阵** | 想纵览全貌 / 汇报 | 按业务域分成几块（MS 综合运维、告警监控、工单流程、网络性能、资源供应链等） |

顶栏可以切换视图。

### 搜索与筛选

- **搜索框**：直接输看板名关键词。
- **筛选**：按分类、平台（FineBI / 自研系统）、标签、部门过滤。
- **只看收藏**：勾上后只显示你星标过的。

### 平台颜色能帮你认来源

- **蓝紫色**的看板来自 **FineBI**（官方报表）；
- **青蓝色**的看板来自**自研系统**（my_app）。

一眼就能知道这张表是什么技术来源。

## 四、顶栏的实时任务部件

门户顶部会显示 my_app 后端**定时任务的实时运行状态**。每分钟自动刷新一次。

怎么看：

| 你看到 | 含义 |
| --- | --- |
| **绿色脉冲点** | 这个面板正在自动刷新，数据是活的 |
| **红点（不闪）** | 取不到数据了，此时显示的是旧内容，注意看时间 |
| 任务后面显示运行中 | 该任务正在跑 |
| 显示上次耗时/成功与否 | 最近一次运行结果 |

> 如果 my_app 后端连不上，这个部件会**自动降级**显示一份静态快照——**不会白屏**，但内容是旧的。

## 五、QC 质量指标面板

一张卡片一个质量指标。这张卡是门户上信息密度最高的部分，值得花一分钟看懂。

### 卡片上三行分别是什么

| 位置 | 内容 |
| --- | --- |
| 第一行 | **指标名称** + 图标。**左侧有 3px 竖条**：蓝=正常，玫红=异常 |
| 中间大字 | **指标数值**。绿色数字 = 有数据；灰色 `—` = **没取到** |
| 第三行 | **统计口径**（这行小字最关键——它说明这个数字是怎么算出来的）。失败时会变成失败原因 |

### 点开看明细

**点卡片任意位置**会弹出明细窗口：

- 表格列出构成这个指标的每一行数据；
- 顶部可以**搜索**；
- 底部可以**翻页**；
- 关掉窗口即可。

### 什么时候刷新

| 类型 | 刷新时间 |
| --- | --- |
| 全量指标 | 每小时 **06 分 30 秒**左右（紧跟后台数据同步任务跑完） |
| 告警类指标 | 每 5 分钟（**00 分 30 秒 / 05 分 30 秒 / …**） |

面板上会显示「更新于 hh:mm:ss」和一个**倒计时**，告诉你下次刷新还有多久。

> 鼠标悬停在刷新信息上，可以看到**两档各自的数据时间**——想知道"其余几项到底有多旧"看这里。

### 两条重要提醒

1. **`—` 不是 0。** 显示 `—` 表示**没取到数**，不是"数量为零"。统计里真的显示 `0` 时，那是**真的一个都没有**。这两者必须分清楚，否则会误判成"已经清空了"。
2. **失败时不会留旧数字。** 一旦取数失败，卡片会直接显示失败原因，**不会**把上一次的旧数字留在屏幕上冒充实时值。

## 六、切换环境（换机器 / 换域名）

顶栏**环境配置**可以一键把**所有**看板链接的 IP/域名批量换掉：

| 预设 | 用途 |
| --- | --- |
| 生产 nginx | 日常使用 |
| vite 7090 直连 | 绕过 nginx 直连前端 |
| 本机调试 | 本地开发 |

也可以用**自定义**填任意主机。切换后所有看板立即生效，不用一条条改。

> 改的是**你自己的浏览器配置**，不影响别人。

## 六之二、OLR 运维门户（`/olbrportal/` 与 `/v1/olbrportal/`）

除了上面这个 React 门户，nginx 还直接发布了两个**手写静态**的 OLR 运维门户：

| 地址 | 说明 |
| --- | --- |
| `/olbrportal/` | 原始版 |
| `/v1/olbrportal/` | 改版（顶栏换 MsPortal 结构、新增六个视图入口卡与 CXO 指标带） |

两边的**看板目录是同一份**（服务端全局目录），在这里改分组，另一边刷新就能看到。
⚠️ 但两边的**编辑对象不一样**：`/olbrportal/` 是在 L1 分组页签面板里改，
`/v1/olbrportal/` 是在页面上那**六个视图入口卡**（CXO / SP / MS / FLM / FO / BO）里改 ——
后者刻意没有再铺一层页签面板（六个入口卡已经覆盖同样的六个分组，多一层就是同一批内容的重复入口）。

### 编辑分组怎么用

顶栏的**「编辑分组」**按钮只有**在服务器本机打开**（或带 `X-API-Token`）时才会出现 ——
局域网访客看到的是纯只读页，这是有意的：这颗按钮改的是**所有人共享**的目录。

点开后页面进入编辑态。**两个门户能做的事略有差别**：

| 想做什么 | `/olbrportal/` | `/v1/olbrportal/` |
| --- | --- | --- |
| 改看板名字 | 卡片上的**改名字** | 入口卡行条目上的**编辑** |
| **改看板链接**（点开看板去哪个页面） | ❌ 没有此入口 | 入口卡行条目上的**编辑** → 同一表单里的**链接**框 |
| 改看板属于哪个分组 | 卡片上的**分组**，勾选位置 | 同上 |
| 组内调整顺序 | 直接**拖拽**卡片 | 直接**拖拽**入口卡里的行条目（只在同列内） |
| 清掉自定义顺序 | 该分组的**重置顺序** | 该列标题旁的**重置顺序**（仅拖过之后出现） |
| 改分组名 / 说明 | 分组面板标题旁的**铅笔** | 该列标题旁的**铅笔**（改完列标题立刻跟着变） |
| 新增一个分组 | 标题旁的**加号** | **最后一列**标题旁的**加号** |
| **把某个看板移出这一列** | ❌ 用**分组**浮层取消勾选 | 行条目上的**移出本列**（看板本身还在，可勾回来） |
| **彻底删除一个看板** | ❌ 没有此入口 | 行条目上的**删除看板**（二次确认，**不可撤销**） |
| **新增一个看板** | ❌ 没有此入口 | 列标题旁的**新增看板**：先选一个已有看板当模板，再填名字与链接 |
| 删除自建分组 | 该分组改名浮层里的**删除** | ❌ 本页没有此入口，请到 `/olbrportal/` 或 MsPortal |
| 归类到子分组 | 把卡片**拖到**子分组标签上 | ❌ 本页没有子分组条，用**分组**浮层改归属 |
| 管子分组 | 子分组条上的**改名 / 删除**、末尾输入框**添加** | ❌ 本页不做 |
| 改地图页签名 | 编辑态下点地图页签 | 同左 |

> ⚠️ **`/v1/olbrportal/` 的新增分组不会在页面上多出一列** —— 页面固定显示那六列。
> 新分组会正常写进共享目录（`/olbrportal/` 与 MsPortal 看得到），
> 想把看板挂进新分组，用卡片上的**分组**浮层勾选即可。这是刻意的，避免本页长出计划外的卡片。

### 删除看板：两颗按钮的区别（`/v1/olbrportal/`）

同一行上有两颗容易混淆的删除类按钮，**用的场合完全不同**：

| 按钮 | 效果 | 能反悔吗 |
| --- | --- | --- |
| **移出本列** | 只把这张看板从**当前这一列**移走，看板本身还在目录里 | ✅ 用**分组**浮层勾回来 |
| **删除看板** | 把这张看板从**共享目录里彻底删掉**，`/olbrportal/` 与 MsPortal 也不再有它 | ❌ 无法撤销 |

> ⚠️ 如果一张看板**只属于这一列**，点「移出本列」会被**拒绝**并提示你改用「删除看板」——
> 因为门户里没有"不属于任何分组的看板"这种状态，移出去就再也找不到了。

### 新增看板：为什么先让你选一个模板

点列标题旁的**新增看板**后，第一步是**从已有看板里挑一个当模板**（可搜索），
第二步才填**看板名**与**链接**。

这样做是因为一条看板的配置有二十来个字段（图标、平台、描述、负责人、部门、标签……），
从零填太费事。选了模板后，这些字段**全部沿用模板**，你只需要改名字和链接。

> ⚠️ **链接一定是空的，名字会带「副本」后缀** —— 这是故意的：
> 照抄模板的链接会造出一张指向同一个页面的重复看板。链接必须以 `http://` 或 `https://` 开头。
>
> 选错模板不用关掉重来，表单底部的**换一个模板**可以退回第一步，已填的名字与链接不会丢。

> ⚠️ **改动立即写入全局目录，所有人可见**，不分"你的"和"我的"。
> 编辑态顶部会有一条横幅反复提醒这一点；改完点顶栏**「退出编辑」**收笔。

### 改看板链接（`/v1/olbrportal/`）

**先解释一个容易误会的地方。** 点开任何一张看板，浏览器地址栏显示的都是

```
http://<主机>/MsPortal/viewer.html?no=13&gid=FLM%20View
```

这**不是**那张看板的真实地址，而是门户的**查看器**地址 —— `no` 是看板编号，`gid` 是它从哪一列点开的。
查看器再去共享目录里按 `no` 查出**真实的链接**，用 iframe 显示出来。
这是有意的一层间接：查看器负责鉴权、主题同步和点击计数。

所以**要换一张看板打开什么，改的是目录里那条记录的「链接」字段**，不是地址栏里那串 viewer 地址。

**怎么改。** 进入编辑态 → 找到那张看板所在的行 → 点行上的**编辑** → 表单里除了中英文名，
还有第三个框**「链接」**，里面预填着当前的地址。改完点**保存**即可，所有人刷新后生效。

> ⚠️ 链接必须以 `http://` 或 `https://` 开头，也**不能清空** ——
> 查看器拿到空链接会显示一片空白。非法值（如 `javascript:`）会被直接拒绝并提示。

**关于链接里的主机名。** 目录里的链接写成 `http://192.168.100.20/…` 这样带主机名的绝对地址，
但查看器**会丢掉主机名**，只保留路径和查询串，再用**你自己访问门户时用的地址**重拼：

```js
// MsPortal/assets/viewer.js — embedSrc()
return location.origin + u.pathname + (u.search || '');
```

所以对**内嵌的 my_app 卡片**来说，写成 `localhost` 还是 `192.168.100.20` 都能打开
（谁访问就用谁的主机）。主机名只在**「新标签页打开」**那颗按钮上才起作用 ——
那里用的是原样地址，写 `localhost` 的话别的同事点会连不上。

> ⚠️ 链接里 `&t=…` 这类查询参数**会被原样保留**。改链接时通常只需要动其中一段
> （例如把 `page=ttwo` 改成 `page=v1_ttwo`），**别把整串覆盖掉**，否则可能丢掉那串参数。

#### 链接后面那串 `&t=…` 要不要填？（多半不用，但也别删）

带 `&t=…` 的链接长这样：

```
http://192.168.100.20/myapp/?page=realtime_alarm&t=<一串很长的十六进制>
```

那是**门户 token**，作用是**免登录**：myapp 启动时会拿它去门户换一个会话 Cookie。
目录里 54 条看板中有 21 条带它，其余 33 条不带。

**好消息是你根本不用输入它。** 点「编辑」时，链接框里**预填的就是当前这一整串**，
你只需要改 `page=` 那一段（比如 `realtime_alarm` → `v1_ttwo`），
保存后这串 token 会**逐字节原样写回**。所以正常改链接的流程里，你碰都不用碰它。

> ⚠️ **但别顺手把它删掉。** 它看着像垃圾参数，其实是"从没登录过统一门户的浏览器"
> 打开这张看板时**唯一的免登录凭据**。删掉之后：
>
> - **你自己**多半没感觉 —— 你登录过门户，浏览器 `localStorage` 里存着同一个 token，
>   myapp 会退回用它；
> - **但**大屏机、同事的机器、或者任何没登录过门户的浏览器点开，就会看到
>   **“Sign in required / 请通过统一门户登录”**，而不是看板。
>
> 这个区别很隐蔽：因为门户后端对**本机访问**（`localhost` / `127.0.0.1`）会自动放行，
> 所以**在服务器本机上怎么试都是正常的**，问题只在别人的电脑上才暴露。
> 实测：`/api/auth/me` 从本机访问返回 `200`（自动认成 `local` 管理员），
> 从 `192.168.100.20` 访问返回 `401`。

**什么时候可以放心删：** 确认这张看板只会被"已经登录过门户"的人打开
（例如只挂在你自己的浏览器书签里）。**拿不准就留着** —— 留着没有任何坏处。

**看不到这颗按钮？** 说明你不是从服务器本机打开的 —— 换到本机，或让管理员配置 Token。

## 六之三、团队可见性（管理员）

门户下面挂着五个团队门户：`/v3/fo_portal/`、`/v3/bo_portal/`、`/v3/flm_portal/`、
`/v3/smc_portal/`、`/v3/cxo_portal/`。每个团队门户的**内容不一样** ——
FO 能看的指标 BO 不一定看得到。

**这份额度由谁定？** 由**管理员**在门户里勾。

### 怎么改

1. 点顶栏右上角的**用户头像** → 展开的菜单里选**「团队可见性」**（只有管理员看得到）。
2. 弹出一张表：左边是**内容条目**（按域分组：QC 指标、KPI、Benchmark、Domain View、
   GIS Map、Knowledge QA、Auto Report、OSS、Complaint、Escalation、Feedback 等），
   右边是**五个团队**，每个团队一列。
3. 勾/取消某个格子 = 该团队能看到/看不到该条内容。
   域标题行上的 **`+` / `−`** 按钮可以**整域批量**选或不选某个团队。
4. 点**「保存」**。

### 保存之后

⚠️ **要刷新团队门户的页面才生效。** 团队门户在页面加载时取一次权限矩阵，
不是实时的。已经在开着的团队门户页面不会自己变。

### 一条重要的默认

**取不到权限矩阵时，什么都不显示。** 不会退回「全部显示」。
这看起来保守，但方向是对的：矩阵可能已经被管理员改过，
拿一份过期的旧矩阵兜底，等于把旧权限又放出来一次。

### 只想「加内容」或「删内容」？

不用管这张表 —— 门户页面上的内容来自上游 `/v3/olbrportal/`。
要让某段内容在团队门户里出现或消失，改的是**上游那页**，
然后由脚本重新生成团队门户那份。详细流程见 `development.md` 的
「团队门户的生成物一致性」一节（开发同事的事）。

### 看不到「团队可见性」菜单？

说明你不是管理员。它只对管理员开放 —— 改团队可见性等于改权限，
不能顺手开放。

## 七、常见问题

| 现象 | 原因 / 怎么办 |
| --- | --- |
| **看不到新增的看板** | 看板配置存在你的浏览器里，**本地设置优先于系统默认**。点顶栏「恢复初始默认看板」即可刷新。注意：这会丢掉你的自定义，先「导出 JSON」备份 |
| 看板点开是空白的 | 目标系统可能没启动或网络不通。先看顶部任务部件是否变红 |
| 二维码手机扫了打不开 | 手机必须和门户在**同一网段 WiFi** |
| 某个 FineBI 报表点进去是目录页 | 该报表链接还是**占位**（标签写着"链接待更新"），要管理员替换成真实 URL |
| 数字一直显示 `—` | 取数失败，看卡片上的失败原因；持续失败请联系运维 |
| 英文界面出现奇怪的英文单词（如 `qc.updated`） | 该处文案缺英文翻译，反馈给开发 |
| 登录报 405 / 登录失败 | 环境异常，联系管理员（技术原因见 `architecture.md` 第二节） |
| 界面某些地方颜色不协调 | 深浅模式切换后个别部件没适配，反馈给开发 |
| OLR 门户（`/v1/olbrportal/`）看不到「编辑分组」 | 只有**从服务器本机打开**才显示（目录是全局共享的，不能让局域网访客随手改）。见第六之二节 |
| `/v1/olbrportal/` 里新建了分组，页面上没多出一列 | 有意如此：本页固定显示六个视图入口卡（CXO/SP/MS/FLM/FO/BO）。新分组已写进共享目录，`/olbrportal/` 与 MsPortal 能看到；挂看板进去用卡片上的「分组」浮层 |
| 想在 `/v1/olbrportal/` 删分组或管子分组 | 本页只提供「改名 / 新建 / 重置顺序」。删分组与子分组管理请到 `/olbrportal/` 或 MsPortal |
| 在 `/v1/olbrportal/` 点「移出本列」没反应 | 如果这张看板**只属于这一列**，会被拒绝（移出去就没有归属了）。要真去掉它，用同一行的「删除看板」 |
| 在 `/v1/olbrportal/` 新增看板，链接框为什么是空的 | 有意如此：照抄模板链接会造出指向同一页面的重复看板。链接必须以 `http://` / `https://` 开头 |
| 新增的看板编号怎么来的 | 取当前最大编号 +1，**不复用已删掉的编号**（旧编号可能还被历史链接或排序记着） |
| 点开看板，地址栏是 `viewer.html?no=…` 而不是看板自己的地址 | 那是门户**查看器**的地址，`no` 是看板编号。真实链接存在共享目录里，要改它：进编辑态 → 行上点**编辑** → 改「链接」框。见「改看板链接」一节 |
| 改了看板链接，但同事那边还是老页面 | 链接存在服务端共享目录里，同事**刷新一下**即可；若还不行，让他确认没在看旧的浏览器缓存页 |
| 链接写成 `localhost` 好不好 | 内嵌的 my_app 卡片无所谓（查看器会用访问者自己的主机重拼）；但**「新标签打开」**用的是原样地址，别人点会连不上。建议跟其余条目一样写 `192.168.100.20` |
