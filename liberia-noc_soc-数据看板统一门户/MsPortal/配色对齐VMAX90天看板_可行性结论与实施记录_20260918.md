## 一、可行性结论

**可行，已全部实施并取证通过。**

三条硬事实：

1. **门户主题是纯令牌驱动的。** `MsPortal/assets/portal.css` 的 `:root` / `html.dark` 两块

## 五、顺带修掉的两处「深色侧」问题（请留意）

浅色补完时发现深色侧有两条规则**一直静默失效**，一并修了。深色的配色令牌、卡片、
顶栏、区块全部逐项比对过，**没有任何颜色改变**；只有下面这两处行为变化：

1. **`--tw-gradient-from/to` 写法错误（22 条声明）**
   `tailwind.css` 里 `@property --tw-gradient-from{syntax:"<color>";initial-value:#0000}`，
   也就是 position 由 `--tw-gradient-stops` 拼，`--tw-gradient-from` 只能是裸颜色。
   原写法 `--tw-gradient-from: <color> var(--tw-gradient-from-position)` 在 `<color>`
   语法下非法 → 回落到 `#0000` → **整条渐变成全透明**。
   影响：深色下 6 个 FineBI beta 链接胶囊原本没有底色，现在恢复成
   `--mp-surface-2 → --mp-surface-flat` 的淡渐变（与规则本意一致）。
   *想回到全透明：删掉 `html.dark .from-slate-50\/80` / `.from-slate-50` / `.to-white` 三条即可。*
2. **`text-teal-600` / `text-teal-500` 漏映射**
   深色下这两个类直接吃 Tailwind 默认 `#0d9488`，压在 `bg-teal-50` 淡底上只有 **3.66:1**。
   现并入已有的 `--mp-tone-teal-fg` 规则（深色 `#6ef0b4`，9.5:1）。

## 五之二、追加修复：查看器内嵌页为什么不是深色（2026-09-18 追问）

**现象**：门户切深色后，点开 `viewer.html?no=37&gid=MS View`，页面看起来还是浅色。

**根因（实测，非推测）**：`viewer.html` 只是个**外壳**，右侧真正显示的是
`<iframe src="/myapp/?page=sync&t=...">` —— 里面是 **my_app 这个独立应用**，
它的主题状态与门户毫无关系。

用 `TMP/diag_viewer_dark.cjs` 抓到的事实：

```
外壳  body 底     = rgb(2, 5, 12)      ← 已经是 vmax 深空蓝 ✅
外壳  sidebar 底  = rgb(7, 16, 39)     ← 已经是深色 ✅
iframe 内 my_app  <html data-theme="light">
iframe 内 html 底 = rgb(233, 238, 243) ← 浅灰，整页看起来就是它
```

也就是说：**外壳早就变深了，是 iframe 里的 my_app 没跟着变。**

**my_app 的主题机制**（读自 `/myapp/assets/index-*.js` 打包产物 + 源码
`D:\01_RPA\Task\my_app\frontend\src\theme.ts`）：

| 环节 | 实现 |
| --- | --- |
| 存储键 | `localStorage['myapp-theme']`（源码常量 `THEME_STORAGE_KEY`） |
| 初始值 | 该键是 `'dark'`/`'light'` 就用它，否则跟随 `prefers-color-scheme` |
| 应用 | `document.documentElement.setAttribute('data-theme', mode)` |
| 对外广播 | 只向**它自己的子 iframe** `postMessage({__type:'myapp-theme', mode})`（给 legacy HTML 工具用） |
| 接收父窗口消息 | ❌ 没有 |
| URL 参数入口 | ❌ 没有 |

所以从外部唯一能驱动它的入口就是 `localStorage['myapp-theme']`。
门户与 my_app **同源**（都在 `http://localhost/` 或 `http://192.168.100.20/`），
共享同一份 localStorage，因此可以直接写这个键。

**改动**（`MsPortal/assets/viewer.js`，新增约 30 行）：

1. 新增 `syncEmbedTheme()`：把 `msportal.theme.v1` 映射到 `myapp-theme`（值不同才写）。
2. `showEmbed()` 里**在赋 `frame.src` 之前**调用 —— my_app 只在启动时读一次，晚了不生效。
3. 「重新加载」按钮里也调用一次，保证手动刷新后主题仍一致。
4. 新增 `storage` 监听：门户在**另一个标签页**切主题时，查看器外壳与内嵌看板一起切并重载。

**验证**：

| 场景 | 外壳 | 内嵌 my_app | 结果 |
| --- | --- | --- | --- |
| 门户浅色 → 打开查看器 | `body #eaf7fb` | `data-theme=light`，html 底 `#e9eef3` | ✅ 一致 |
| 门户深色 → 打开查看器 | `body #02050c` | `data-theme=dark`，html 底 `#0a1929` | ✅ 一致 |
| 查看器开着时在门户标签页点主题切换 | `class=dark`，`body #02050c` | `data-theme=dark` | ✅ 跟随（`TMP/verify_viewer_xtab_sync.cjs`） |

深色截图主色（`TMP/cmp/viewer-dark.png`）：`#2c1618 31.4%`（内嵌页里的深红面板）、
`#071027 17.2%`（查看器侧栏）、`#0a1c2c / #0d2234 / #0b1e32`（my_app 深海军蓝各档）
—— 整页已是深色。

**顺带**：`viewer.html` 的 `#frame { background: #fff }` 写死了白色，iframe 文档还没绘制时
会先闪一块白。已改为 `var(--panel-2)`，深色下是 `#050d22`。

**回滚**：删掉 `viewer.js` 里 `EMBED_THEME_KEY` 那段 + 3 处 `syncEmbedTheme()` 调用 +
`storage` 监听即可（`#frame` 那行 CSS 可单独留着，它只是消除白闪）。

## 五之三、my_app 自身深色也换成 vmax 口径（2026-09-18 第三轮）

**背景**：上一步只让内嵌页「跟着变深」，但 my_app 用的是**它自己的深色色板**
（深海军蓝 `#0a1929` + 青绿 `#64ffda`），和门户的 vmax 口径（近黑 `#02050c` + 电光青
`#00d9ff` + 实心宝蓝描边 `#153db0`）不是同一种深色。按要求把 my_app 的深色也换过来。

### 改动范围

| 层 | 文件 | 说明 |
| --- | --- | --- |
| DOM 令牌 | `frontend/src/index.css` | `:root`（默认深色，2–125 行）+ `:root[data-theme='dark']` 各规则 |
| JS 令牌 | `frontend/src/theme.ts` | `DARK` 常量、`WH_COLORS` 系列表、`darkTooltip` / `axisLabel` / `axisLine` / `splitLine` 的深色分支 |
| antd | `frontend/src/App.tsx` | `ConfigProvider` 的 `colorPrimary/colorInfo/colorSuccess/colorWarning/colorError` 加 `isDark` 分档（浅色档保持 antd 原值） |
| 组件内联 | 19 个 `.tsx` | 内联样式 / ECharts 色值里的旧深色字面量 |

**22 个文件、317 处替换 + 15 条结构性令牌校准。**

### 关键做法：按「安全边界」分两类替换

盲目全局替换会**改坏浅色**。例如 `EflowQa.tsx` 里
`isDark ? '#94a3b8' : '#64748b'` —— 第二个是**浅色分支**，若一起换成 `#6f8cb4`，
在白底上只有 3.6:1，比原来的 4.75:1 还差。所以分两类：

- **A 类｜旧深色专有**：`rgba(100,255,218,α)`、`#64ffda`、`#4fc3f7`、`#7986cb`、
  `#0a1929`、`#0d2138`、`#141f33`、`#112540`、`#e6f4ff`、旧玻璃底各档 `rgba(...)`…
  —— 浅色分支从不用这些值，**可全文件替换**。
- **B 类｜深浅共用语义色**：`#94a3b8`、`#64748b`、`#ff4757`、`#ffd43b`、`#51cf66`、
  `#ff6b6b`、`#ffa940`、`#ff8788`、`#13c2c2`… —— **只在深色上下文里替换**。
  深色上下文的判定覆盖四种写法：
  1. `isDark ? '#xxx' : …`
  2. 对象字面量键 `{ dark: '#xxx', light: '#xxx' }`（`NurDashboard` 的系列色表）
  3. 模板字符串里选择器含 `dark` 的 CSS 规则体（`DraggableClickModal` 的 `.dcm-dark`）
  4. `.css` 里 `:root` 深色块 / 选择器含 `dark` 的规则

  脚本：`TMP/patch_myapp_dark_vmax.cjs`（先 `--dry` 出报告，确认后才 `--apply`）。

## 五之四、追加修复：浅色下查看器侧栏顶部仍是深色方块（2026-09-18 第四轮）

**现象**：浅色主题下，查看器侧栏顶部那块「MS View / 综合运维管理层 / 8 个看板」还是深色。

**根因**：`viewer.html` 第 59 行

```css
.sb-head {
  padding: 14px 16px 12px; border-bottom: 1px solid var(--border);
  background: linear-gradient(180deg, #080f43, #070d31); color: #fff;   /* ← 写死 */
}
```

第一轮把 `.sb-head` 换成 vmax 的 mast 渐变时，**只换了深色那一档，没做主题分档** ——
它成了整个 `viewer.html` 里**唯一一处不走令牌的颜色**（其余全部 `var(--*)`）。
所以浅色下它一直保持深海军蓝。

**修法**：新增 4 个令牌，深浅各一套；同时把 `.sub` / `.cnt` 的 `opacity: .72 / .6`
换成显式 `color` —— 否则浅色下会被稀释到 4.5:1 以下。

```css
:root {                       /* 浅色 */
  --sb-head-bg:  linear-gradient(180deg, #f2fbfd 0%, #e7f1fa 100%);  /* vmax 浅色表面档 */
  --sb-head-fg:  #12324a;     /* 门户浅色 mast 标题色 */
  --sb-head-sub: #526b7d;     /* --text-2 */
  --sb-head-cnt: #596f85;     /* --text-3 */
}
html.dark {                   /* 深色：与原来逐像素一致 */
  --sb-head-bg:  linear-gradient(180deg, #080f43, #070d31);
  --sb-head-fg:  #ffffff;
  --sb-head-sub: rgba(255,255,255,.72);
  --sb-head-cnt: rgba(255,255,255,.60);
}
.sb-head      { background: var(--sb-head-bg); color: var(--sb-head-fg); }
.sb-head .sub { color: var(--sb-head-sub); }
.sb-head .cnt { color: var(--sb-head-cnt); }
```

> 深色为什么能保证不变：原来的 `opacity:.72/.6` 是叠在**不透明**的 mast 渐变上的，
> 结果与直接写 `rgba(255,255,255,.72/.60)` 完全相同。深色截图逐点比对确认一致。

**取证**（`TMP/verify_viewer_sbhead.cjs`，用「元素真实位置 + 截图背景像素」算实际对比度，
不是拿令牌值估算）：

| 元素 | 浅色 | 深色 |
| --- | --- | --- |
| `.grp` "MS View" 15px/700 | ✅ 12.31:1 | ✅ 18.43:1 |
| `.sub` "综合运维管理层" 11.5px | ✅ 5.06:1 | ✅ 9.80:1 |
| `.cnt` "8 个看板" 11px | ✅ 4.63:1 | ✅ 7.09:1 |

侧栏顶部 268×86 区域的**实测平均色**：浅色 `#e6f0f6`（亮度 0.858，是浅块）、
深色 `#101641`（亮度 0.011，与改前一致）。

**顺带做了一个客观工具**：`TMP/png_darkregions.cjs` —— 对截图做连通域分析，
找「大面积连续深色区域」。文字字形是细小连通域会被面积阈值滤掉，真正的深色块是巨大连通域。
跑遍所有浅色截图：

| 截图 | 结果 |
| --- | --- |
| 查看器 浅色（修复后） | ✅ 无深色块（最大深色连通域仅 0.05%，属文字） |
| 查看器 深色（对照组） | ⚠ 1 块，占比 96.8% —— 工具自检通过 |
| 门户首页 浅色 | ✅ 无深色块 |
| my_app 浅色 | ✅ 无深色块 |

**回滚**：把 `viewer.html` 第 72 行改回 `background: linear-gradient(180deg, #080f43, #070d31); color: #fff;`
并恢复 `.sub`/`.cnt` 的 `opacity`（或直接用备份 `viewer.html_bak_20260918_vmax90Days配色前`）。
