### 更正（重要）：200201001 会建 TT —— 有**无条件兜底派发** #164

  条件为空 / ACTIVE / 优先级 3** → **对任何告警码都生效**。按「规则条件里是否枚举了这个码」
  去查永远查不到它，于是会把「会自动建 TT」答成「没有任何规则引用它 → 不支持」。
- `#165 TT单直接派BO accept` 是**按 `netWorkType in (CS,PS,VAS,OCS)`** 匹配（优先级 2，比 #164 靠前）
  → 这类码会被接进 **BO 线**，而不是 FO 线。只按码查同样查不到。
- 定级：没有专门 ttLevelRule → 兜底 `#230 TT-lowest severity → P4`（条件 vipSite=0/1）。
- 推单：没有任何 ttPushOrderRule 引用 → 不推 ZTE_NOC_FO / BO / 第三方。

所以正确结论是**分开下**：
- 压缩：eFlow 没配关联/衍生规则 → **不压缩**，告警独立上送；
- 建单：**会建**，走兜底派发 #164（netWorkType 命中 #165 则进 BO 线），级别 P4；
  「没配」= **没有专门处理路径**，≠「不建单」。

`ticketConfigured` 计入父告警的定级规则，避免「上面说定级 #227、下面说没有定级规则」自相矛盾。

## 模型输出净化：mimo 把思维链/工具调用标记漏进 content（15:40 修复）

现象：`npm run ask "今天天气怎么样"` 偶发（实测约 1/4）把整轮回复变成
`I'll check the available tools for querying site alarm and ticket status.
<tool_call><function=mcp-eflow-ops-kb-mcp__search_knowledge>…` ——
一个字的答案都没有，却以 `命中=true`、`answered=true` 发进群里。
另一种形态是正文前挂一句 `Wait — the question is…</think>`。

根因：`src/llm.js` 的 `openaiChat` 只处理了「content 为空」和「只有 reasoning_content」
两种情况，对「content **非空**但全是标记」毫无防备。而 mimo 的思维链是拆到
`reasoning_content` 的，`content` 里只**漏出闭合标签**，所以前半句思考也留在了正文里。

修复（`src/llm.js`）：
- 新增导出 `stripModelMarkup(raw) → {text, think, toolCall}`：
  完整/未闭合 think 块剥掉；**孤立闭合标签前面那段文字一并丢弃**（那就是思考内容）；
  `<tool_call>` / `<function=x>` / `<parameter=x>` 一并剥离（注意实测的 `<function=x>`
  是不带右尖括号的开标签，`[^>]*` 匹配不到，得单独用 `<function\s*=[^>]*>`）。
- 出现工具调用标记 → **整轮判为不可信**（哪怕剥离后还剩一句旁白），
  在 `openaiChat` 里自动重打一次（`opts.maxAttempts`，默认 2）。
  只有标记泄漏才重试；纯 content 为空（思考烧光预算/被截断）不重试，重打也是空。
- `stats.attempts` 记录重试次数；`degraded=think_stripped` 标记「剥过思考」。
- HTTP 调用抽成 `postCompletion()`，重试不必重复错误翻译；`totalMs` 从进函数算起，
  重试时如实反映用户等了多久。

配套（`src/rag.js`）：
- `answer()` 生成后若 `content` 为空 → 不再 `answered:true, text:''`（群里收到空消息），
  改为回 `groundExcerpt()` 原文摘录（无摘录则 notFoundText），`stats.emptyContent=true`。
- `retryWithRewrite()` 二跳生成空 → 返回 null，交回调用方兜底。
