# my_app 生产环境清理候选清单

检查日期：2026-09-08  
检查范围：`Y:\Task\my_app`  
检查方式：只读目录与配置检查；本轮未删除、未移动任何文件。

## 结论摘要

项目中确实存在可清理的**运行时缓存、编译缓存、临时诊断产物和可能过期的日志**，但生产环境不应按目录名直接批量删除。优先级如下：

- **高置信度、可在停服/确认后放入回收站**：Python `__pycache__` / `*.pyc`；前端 `node_modules`（仅当本机不承担构建/开发职责）；明确属于一次性检查的 TMP 诊断副本。
- **需要保留策略后再处理**：`log\` 下历史日志、`backend\*.pid`、`frontend\node_modules`、迁移检查日志与报告。
- **不建议清理**：生产数据库、WAL/SHM 边车文件、上传文件、业务数据、凭据/环境配置、部署脚本、正式前端静态资源、项目文档归档。

## A. 高置信度候选

| 候选路径/模式 | 判断依据 | 生产风险 | 建议 |
|---|---|---|---|
| `backend\__pycache__\` 及项目内其他 `__pycache__\` | Python 编译缓存，源码可重新生成；已看到 `backend\__pycache__\` 内有多个 `.pyc` | 运行中的 Python 进程不会因删除已加载字节码而立即中断；若正在启动/重启，可能产生竞态 | **停后端和 worker 后**，整目录移入回收站；下次启动会重建 |
| `backend\scripts\__pycache__\`、`backend\migrations\__pycache__\` | 同上，属于脚本/迁移模块编译缓存 | 低，但不要在进程启动或迁移执行时操作 | 停服后移入回收站 |
| `TMP\_*.png`、`TMP\_*.txt`、`TMP\_*.json`、`TMP\_*.html` 等一次性诊断产物 | `TMP` 目录中大量文件带 `_check`、`_dbg`、`_test`、`_probe`、`_recover`、`_pid`、截图等命名，明显包含调试/验证输出 | 可能仍被某个排障脚本引用；无法仅凭文件名确认业务无引用 | 逐项确认最近不再使用后移入回收站；**不要删除整个 `TMP` 目录** |
| `frontend\node_modules\` | 第三方依赖安装目录，可由 `frontend\package-lock.json` + `npm install` 重建 | 若本机负责前端构建/开发，删除后会导致构建暂时不可用；生产静态服务若只提供已构建资源则通常不需要 | 只有确认本机不再构建前端时才清理；保留 `package.json` 与 `package-lock.json` |

## B. 需要保留策略后再处理

| 候选路径/模式 | 判断依据 | 生产风险 | 建议 |
|---|---|---|---|
| `log\` 中明显为旧调试/诊断的日志：如 `killlog*.txt`、`pidcheck.txt`、`proc_*.txt`、`nginx_*.txt`、`*_console.log`、`*_probe*.log`、`*_analysis.log` | 目录内同时存在运行日志、watchdog 日志、错误日志和多批排障记录；不能按名称判断是否仍用于审计/故障追踪 | 删除当前日志或缺少审计记录会影响生产排障；正在写入的日志不能移动 | 建立保留期后处理（例如按天/按周归档）；先确认文件未被进程占用，再逐个移入回收站。`backend_runtime.log`、`worker_runtime.log`、watchdog 日志默认保留 |
| `backend\*.pid`：`backend_watchdog.pid`、`worker_*pid` 等 | 进程 ID 文件属于运行时控制文件；项目 `.gitignore` 已明确忽略 `*.pid` | 若服务仍运行或启动脚本依赖它们，删除可能造成重复启动、停止失败或误判进程状态 | 先确认对应进程已停止且 PID 已失效，再移入回收站；不要在服务运行中操作 |
| `alembic\` 下 `r2_check_run*.log`、`r2_post_write_check*`、迁移检查报告 | 可能是一次性迁移/回归验证产物，但也可能是当前迁移审计依据 | 删除会丢失数据库变更审计证据；迁移未完成时风险高 | 由数据库迁移负责人确认“已归档”后再处理；迁移脚本本身不要删除 |
| `2026-09-05\`、`2026-09-07\` 下的历史交付目录 | 看起来是以前生成的交付物/任务目录，不属于代码运行路径 | 可能包含用户需要的交付物，不能按日期判定过期 | 与交付物负责人确认后整体归档或移入回收站；本次 `2026-09-08\...` 目录是本任务输出目录，不应清理 |

## C. 明确不建议清理

| 路径/模式 | 原因 |
|---|---|
| `db\app.db`、`db\uploads\`、`backend\app.db` | 生产数据库及上传数据；删除或移动可能直接造成业务数据丢失。两个 `app.db` 均需先确认实际运行路径，不能凭文件名处理。 |
| `data\` 下各类 SQLite/JSON/Excel 数据 | 包含 KPI、告警、拓扑、报表及同步数据，属于业务数据或数据源。 |
| `*-wal`、`*-shm` | SQLite 正在使用时是数据库一致性组成部分；项目 `.gitignore` 的忽略规则不代表可删除。仅能在确认数据库完全停止并按 SQLite 备份/恢复流程处理。 |
| `backend\.env`、`CREDENTIALS_LOCAL_REFERENCE.txt`、任何 credential/auth/cache 文件 | 可能包含连接配置、凭据引用或鉴权状态；不可按“本地文件”清理。 |
| `start*.bat`、`stop.bat`、`*.vbs`、`*.ps1`、`mw_links_sync.bat` | 生产启动、停止、看门狗和同步入口；删除会破坏运维操作。 |
| `frontend\dist*`（若存在）、`frontend\public\`、`frontend\src\` | 可能是发布资源、静态页面和源代码；必须由构建/发布流程确认后才能处理。 |
| `PROJECT_DOCS.md`、`PROJECT_DOCS_ARCHIVE.md`、`docs\manual\` | 文档中明确存在迁移、架构和历史审计依据；`PROJECT_DOCS_ARCHIVE.md` 明确是原文备份，不应当作垃圾文件。 |
| `requirements.txt`、`requirements.lock.txt`、`frontend\package.json`、`frontend\package-lock.json` | 依赖安装和可重复构建所需的清单；不可清理。 |

## 推荐的安全处理顺序

1. 先确认当前后端、worker、watchdog 和前端构建进程状态；运行中的生产服务不直接操作日志、PID 或数据库边车文件。
2. 先备份需要保留的日志/迁移审计记录，并记录文件路径、时间范围和备份位置。
3. 优先处理 Python `__pycache__`，再处理已确认无引用的 TMP 一次性诊断文件。
4. 若本机不承担构建，再处理 `frontend\node_modules`；否则保留。
5. 对日志和 PID 文件执行保留期策略，而不是一次性清空。
6. 所有删除动作都应是“移动到 Windows 回收站”，并在移动后验证原路径已不存在、回收站中存在对应项目；不使用永久删除命令。

## 本轮限制

原计划通过 shell 同时读取 Git 状态、文件时间和大小，但本轮本地命令执行闸门未响应，该命令未实际执行。因此本清单没有把“文件很久未修改”或“当前未被进程占用”当作事实；这些项目在真正移动前必须再次核验。
