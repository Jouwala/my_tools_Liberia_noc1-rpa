用户三条要求：
① Summary-Current 加 Inventory 表的 `Domain` 列，**放第 2 列**；
② `Safety Stock` 后面加一列备注：**月均消耗为 0 → Safety Stock 设 1、备注「故障率」**；
   月均消耗不为 0 → 备注「实际消耗」；

### 改动（`backend/services/sp_report_gen/gernarate_sp_report.py`）

- **Domain 列（第 2 列）**：`build_summary()` 里从 `inv_df` 按 `Material Name` 取第一个非空 `Domain`
  （`drop_duplicates('Material Name')` + `map`），列顺序改为
  `Material Name, Domain, Inbound Qty, Outbound Qty, Inventory Qty, Balance, Difference`。
  `Total` 行 Domain 留空。Inventory 没有 `Domain` 列时降级为全空、不报错。
- **Remark 列**（`Safety Stock` 之后，第 10 列）：
  - 常量新增 `REPLENISH_REMARK_COL` / `REPLENISH_NO_CONSUMPTION_SAFETY = 1` /
    `REMARK_FAILURE_RATE = 'Failure Rate'` / `REMARK_ACTUAL_CONSUMPTION = 'Actual Consumption'`。
  - `build_replenishment()`：`has_consumption = avg > 0`；
    `safety = np.where(has_consumption, avg * 6, 1.0)`；`Remark = np.where(..., 'Actual Consumption', 'Failure Rate')`。
  - **连带效果**：原来「安全库存 0 → Alert Level 一律 Excess」的兜底逻辑作废，
    现在无消耗物料的 Alert 按 `库存 / 1` 判：库存 0 → Urgent、库存 1 → Replenish、≥2 → Excess。
    `REPLENISH_COLS` 顺序变成 `Material Name, Avg, Safety, Remark, Replenishment Qty, Alert Level`。
  - `Total` 行的 Remark 也置空（和 Alert Level 一样，合计无意义）。
- **口径说明从 2 行扩到 3 行**：新增第 3 行
  `Remark: Failure Rate = Avg Monthly Consumption is 0 (Safety Stock floors at 1) | Actual Consumption = Avg Monthly Consumption > 0`。
  → **Summary-Current 表头从第 6 行下移到第 7 行**，数据从第 8 行开始。

### 踩到的验证坑

`build_summary()` 里空 Domain 写的是 `''`，但 `to_excel` 后空字符串变空单元格、`read_excel` 读回 **NaN**；
验证脚本复算时 `fillna('')` 得到 `''` → `'' != NaN` **误报 32/23 行不一致**。
→ 复算侧不要 `fillna('')`，让它保持 NaN，比对时两边统一 `fillna('~')` 即可。**这类「空值的两种表示」是复算比对的常见假阳性。**
