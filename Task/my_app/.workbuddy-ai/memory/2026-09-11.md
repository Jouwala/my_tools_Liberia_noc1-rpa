### 口径确认（用户已确认）
- 数据源 = 本地小区可用率库 `data/ran_kpi_avalability_1day.sqlite3`（GSM/UMTS/FDD/TDD），
  由既有任务 `cell_availability_sync` 从 RAN_UME 拉取。
- 4G = **FDD 全部小区**（不用远端 4G_Main_Kpi_Cell_Daily）。
- 逐小区可用率折算：
  - 2G(GSM)：可用信道 / 全部信道，其中
    可用 = 静态 TCH/H + 静态 TCH/F + 平均可用动态信道；
    全部 = 可用 + 不可用定义 TCH/F + 平均不可用动态信道 + 不可用定义 TCH/H。

  - 3G(UMTS)：`Service time of the cell(s)` / 86400
  - 4G(FDD)：`Cell Service Time(s)` / 86400
- 统计：Total = Meeting + Below；Blank = 当月小区名册（roster = 当月出现过的全部小区名并集）内
  当天无有效值的小区数；% = count/Total；Availability = 当天有效小区可用率算术平均。
- 校验：2026-09-01 算出 2G total 3138 / blank 15 / avail 97.45%，3G 4507 / 0 / 98.26%，
  与参考图（3139 / 15 / 97.45%，4509 / 0 / 98.24%）吻合。

## 修复 start_hidden.ps1「假 OK」缺陷（用户选择「先修缺陷再重启」）

改动位置：`Ensure-BackendWatchdog` 的 `-Force` 分支（`start_hidden.ps1` 第 161–192 行）。
**仅新增校验与如实上报，未改变杀进程行为。**

- `-Force killed` → `-Force killing`（措辞：先杀后验）。
- `Stop-PidForce $owner` 之后新增：重新读取 `Get-NetTCPConnection -LocalPort 7038 -State Listen`
  的 `OwningProcess`：
  - 仍是同一 pid → `[FAIL] Port 7038 still held by pid={0} after -Force kill: taskkill was denied
    (insufficient privilege).` + 三行 ACTION 提示，`failCount++`，**放弃本轮拉起**（`return $false`）。
  - 换成了别的 pid → `[WARN] re-occupied by another pid (possible race)`，继续。
  - 取不到（端口已释放）→ `[OK] Port 7038 released (pid={0} terminated)`，继续。
- 取舍说明已写进代码注释：放弃拉起的代价是「孤儿消失后恢复要等下一次巡检（≤5 分钟）」；
  这是有意的——被卡住的端口必须人工介入，跑一个永远绑不上端口的 watchdog 只会制造噪音。
- `start_ensure.bat` 末尾是 `exit /b 0`，故 `failCount>0` 不会让计划任务报错，
  只在结果文件里如实体现（`===== Result: 1 failures / 1 warnings =====`）。
