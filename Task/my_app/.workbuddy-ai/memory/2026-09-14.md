## 修复：看板首次打开报 401「Failed to load data」，刷新才好

### 现象
打开 `http://192.168.100.20/myapp/?page=ran_cells_kpi`（从门户卡片/深链进入）首屏报
`Failed to load data / Request failed with status code 401`，按 F5 刷新后正常。

### 根因（前端启动时序竞态）
- 门户卡片跳转 URL 形如 `/myapp/?page=ran_cells_kpi&t=<门户token>`（门户 `resolveUrl()`
  在 localStorage 有 `liberia_noc_auth_v1` 时追加 `&t=`）。后端 myapp 数据接口强制鉴权
  （`MY_APP_DB_MODE=pg`，会话表 `portal_sessions`，中间件见 `backend/main.py`
  `require_session_middleware`；本机回环 `client_is_local` 放行）。
- 原 `App.tsx` 在 `useEffect` 里异步调 `portalLogin(?t=)` 换会话 Cookie，而业务页面
  同时挂载并立刻请求 `/api/ran-cells-kpi/overview` → Cookie 还没落地 → 401。
- `RanCellsKpi` 只在挂载时取一次数、不重试，故错误一直挂在页面上；刷新时 Cookie 已存在 → 正常。
- 次要问题：`TaskStatusProvider` 也抢跑 `/api/tasks`（同为鉴权接口），导致登录引导闪屏。

### 修法（把「换会话」提前到 React 渲染之前）
1. `frontend/src/api.ts` 新增 `readPortalToken()` / `bootstrapAuth()` / `runAuthBootstrap()`：
   - token 来源：URL `?t=`（取到即 `replaceState` 抽走）→ 兜底读同源 localStorage
     `liberia_noc_auth_v1`（myapp 与门户同源，书签/手输 URL 也能免登录）；
   - 换会话失败则退化为 `getAuthMode()`（免登录模式）→ `getAuthMe()` 判会话，返回是否已具备身份。
2. `frontend/src/main.tsx`：`Promise.race([runAuthBootstrap(), 8s 超时])` 完成后再
   `createRoot().render()` —— 页面挂载时 Cookie 必然已就绪。
3. `frontend/src/App.tsx`：删掉原 `?t=` 异步换会话；新增 `bootDone`，
   `!bootDone || authGate` 时不挂载业务页面（显示 Spin），未登录直接给门户登录引导。
4. 源码备份：`frontend/src/{api.ts,main.tsx,App.tsx}_bak_20260914_authfix`。
