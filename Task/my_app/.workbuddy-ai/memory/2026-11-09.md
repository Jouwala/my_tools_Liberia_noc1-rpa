## 修「https://localhost/MsPortal/viewer.html?no=66&gid=BO View」打不开 / localhost sent an invalid response

**根因（实测确诊）**：B2 整改后 80 口强制 301 到 443，主站恒为 https。前端生成的
独立端口门户反代地址 —— `ImonitorScreen.tsx::portalBase()` 用 `location.protocol`、
`PortalLogin.tsx` 用 `PROXY_PREFIXES` 的协议相对 `//{HOST}:808x` —— 在 https 页面上
全部拼成 **https://<host>:808x**，而 `conf/portal_ports.conf` 里 8081-8086 / 8088
一直是**明文 HTTP**。TLS ClientHello 打过去收到明文响应 → Chrome
`ERR_SSL_PROTOCOL_ERROR`（错误页文案正是「localhost sent an invalid response」）。
`curl https://localhost:8088/` 报 `SEC_E_INVALID_TOKEN`，`http://` 200，可快速复判。

**为什么不能改回 http://**：https 页面嵌 http iframe 会被混合内容拦截，只有
localhost/127.0.0.1 例外，经 192.168.100.20 访问的同事必然白屏。

**排查手法（可复用）**：Playwright（系统 Python312，Chromium + `--no-proxy-server`
+ `--ignore-certificate-errors`）加载页面后遍历 `page.frames` 与 `requestfailed`，
能直接看到内层 iframe 的 `ERR_SSL_PROTOCOL_ERROR`；再按 `/api/portal-catalog` 的
63 个 item 批量回放 `viewer.html?no=<no>&gid=<gid>`（修复前 1 坏 / 63，修复后 0 / 63）。
nginx `access-$hostname.log` 里用户请求其实是 200 —— **页面外壳成功、内层 iframe 挂**
时不要只看顶层状态码。

**改动**：
- 生效配置 `D:/01_RPA/nginx-1.28.0/conf/portal_ports.conf`：http 级加
  `ssl_certificate/key/protocols/ciphers`（复用 443 自签证书，SAN 含
  .20/.19/localhost/127.0.0.1）；7 个 `listen 808x;` → `listen 808x ssl;` +
  `[::]:808x ssl`；7 条 `proxy_redirect ... http://$host:808x/` → `https://`。
  备份 `portal_ports.conf.bak_20261109_https_ports前`。
- `conf/portal_eflow_common.conf:44`：`sub_filter_types` 去掉显式 `text/html`
  （它是内置默认，写了会刷 5 条 duplicate MIME type）。已验证 eFlow 登录页
  `/api/portals/inject.js?system=eflow` 注入仍在，HTML 过滤没丢。
- 前端 `ImonitorScreen.tsx::portalBase()` 固定 `https://<hostname>:8088`（端口协议由
  nginx 决定，不随宿主页协议变）；`PortalLogin.tsx` 给协议相对前缀显式补 `https:`。
  用托管 Node 直接 `vite build`（**不走 npm run build**）出到 `_fe_dist`，
  入口 chunk `index-BgIGqb07.js` → `index-9ynsP9g9.js`。
- 仓库留档同步：`nginx/portal_ume_in_8088.conf`、`portal_zte_ume_8081.conf`、
  `portal_eflow_rewrite.conf`；`backend/services/portal_login_service.py` 的
  PROXY_PREFIXES 注释补口径（**值没改**，故不用重启 7038）。
- `nginx -t` + `nginx -s reload` 两次（pid 文件 = 7992，正是指挥所有 LISTENING
  套接字的 master）。reload 不中断站点。

**验证**：8081-8086/8088/9443 的 https 全部 200/302/404（TLS 握手成功即可，404 是
上游根路径本来就没有）；`http://...:808x` 现在回 nginx 400「plain HTTP sent to
HTTPS port」，属预期。8 个 client-login 门户 URL 全部 200/302；63 个看板回放 0 坏页；
iMonitor 内层 iframe 已落到 `https://localhost:8088/...`，零协议错误。

**遗留（与本次故障无关，别混为一谈）**：iMonitor 自动登录停在 authorize 页 ——
`/api/oauth2/v1/login_rsa` 回 401，页面文案「The user password is about to expire
[com_zte_ums_aos_sm_user_continue_login]」，是上游 UME 账号 10172755 密码将过期、
需要多点一次「继续登录」，不是 TLS/反代问题。要修得改
`portal_login_service.build_inject_js` 并重启 7038。

**运维备注**：本机仍有 2 个 17:51 启动的陈旧 nginx master/worker（72976/77936），
它们不持有任何 LISTENING 套接字，无害；`nginx.pid`=7992 有效，reload 正常。
⚠️ 8081-8088 现在是 **HTTPS-only**，任何 `http://host:808x` 的书签/脚本都要改 https。
