# 2026-09-19 工作日志

## legacy 单文件页「深色档」统一到 vmax 深空蓝（接续 2026-09-18 的外壳统一）

### 用户报告的现象与根因

用户：「深色主题好像没有完成跟 `?page=vmaxCxoDashboard_90Days` 一样，如 `?page=mwRealTime`，请分析下如何处理。」

**根因**：my_app 的界面由**两套互不相干的调色系统**画出来：

1. **React 外壳层** —— `frontend/src/index.css` 的 `--wh-*`、`theme.ts` 的 `WH/DARK`、
   `App.tsx` 的 `VMAX_DARK_TOKEN`（antd）。2026-09-18 已统一到 vmax 深空蓝。
2. **legacy 单文件 HTML 层** —— `frontend/public/*.html`，经 `LegacyToolFrame.tsx` 以**同源 iframe**
   嵌入。这些页各自在 `<style>` / JS 里**自带一份私有调色板**，只与外壳共享「深/浅档这个
   状态」（`html[data-theme]` + `localStorage['myapp-theme']` + `postMessage({__type:'myapp-theme'})`），
   **从不共享色值**。

于是外壳是 vmax 深空蓝、iframe 内部还是各页自己的老配色，接缝处直接看到一条颜色台阶。
实测（深色档 iframe 的 `body` 底色）：

| 页面 | 改前 | 基准页 |
|---|---|---|
| `?page=mwRealTime` | `#03141d`（墨绿青） | `?page=vmaxCxoDashboard_90Days` = `#02050c` |
| `?page=mwUmeTopology` | `#03141d` | 同上 |
| `?page=cxoDashboard` | `#03141d` | 同上 |
| `?page=alarmManagement` | `#0a1929`（slate） | 同上 |
| `?page=warehouse` | `#0a1929` + 薄荷绿 `#64ffda` | 同上 |
| `?page=incident_overview` | body 透明 + Tailwind `#e5e7eb`/`#94a3b8` | 同上 |
| `?page=ip_trace` | `#090c15` + 强调青 `#00dbc9`（**且完全没有主题机制**） | 同上 |

**这不是「某一页忘了改」，而是「逐页私有调色板」这个结构本身的必然结果** ——
只要色值有 N 份副本，就有 N 个漂移点。

### 方案（用户选定）

- 范围：**先修 `mwRealTime` 试点，验证映射口径后再铺开**。
- 做法：**抽 `legacy-vmax-theme.css` 单一真相源 + JS 读 CSS 变量**。

### 交付物

**① `frontend/public/legacy-vmax-theme.css`（新增，深色档唯一真相源）**

- 定义全部 `--vmax-*` 令牌（背景四层 / 描边四档 / 文字四层 / 主色强调 / 语义色 /
  7 级健康度色阶 / 蓝色叠加填充 / 卡片渐变·内辉光·顶栏 mast·页面辉光 / 蒙版）。
- 提供**兼容别名**（`--bg --panel --panel2 --line --line-soft --accent --text --muted
  --green --yellow --orange --red --gray`、`--border --border-strong --panel-sub`、
  `--accent2 --good --bad`）→ 各页 CSS **一行都不用改**，只删自己的深色定义块即可。
- 提供**观感开关** `--surface-bg` / `--surface-shadow`：深色 = vmax 卡片渐变 + 内辉光；
  浅色由 `html[data-theme="light"]` 统一兜底复位成「平涂 + 无阴影」（各页自己的 light
  块特异性同为 (0,1,1) 且文档顺序在后，仍可覆盖）。
- 提供 **Tailwind CDN 桥接** `--vmax-*-rgb` 三元组：Tailwind 的 `/30` 透明度修饰符要求
  色值可解析，直接写 `var(--vmax-cyan)` 会让 `parseColor()` 返回 null 并**静默丢弃透明度**
  （`bg-primary/30` 退化成不透明整块）。正确写法 `rgb(var(--vmax-cyan-rgb) / <alpha-value>)`。
- 文件头写明**三步迁移法**与**维护约定**（改色必须同步 `index.css :root` 与
  `App.tsx VMAX_DARK_TOKEN`）。

- `TMP/t_legacy_dark_rollout_verify.py`：**全量独立复核**。把每页改动前备份复制成
  `_fe_dist/_orig_<name>.html` 作为**浅色档回归基线副本**（相对资源路径不变，可直接打开），
  逐页测 `{基线, 现版} × {深色, 浅色}` 四组数据，断言深色基色/主文字 + 浅色与基线逐项一致。

- `TMP/t_legacy_light_elementdiff.py`：**浅色档逐元素核对**（比 body 底色严格得多）。

  为什么用多重集：现版比基线多一个 `<link>`，按索引比会让其后元素整体错位、全是假差异。

### 浅色档保真：靠「逐元素核对」才挖出来的 3 个真问题

只比 body 底色/主文字是不够的 —— 加了逐元素核对后，mw 两页暴露出 53/79 个元素的浅色档颜色变了，
顺藤摸瓜挖出三个真 bug：

1. **CSS 注释提前闭合吞声明**（最隐蔽）。浅色档注释里写了「`.lvl-*/.dot-*` 的浅色观感」，
   其中 `*/` **提前闭合了注释**，紧随其后的 `--vmax-lvl-healthy:#0f9d6b` 被 CSS 错误恢复
   逻辑当成乱码吞掉，于是浅色档 healthy 一档静默回落成深色值 `#0bc78c`。
   **页面不报错、其它 6 档全对**，只有逐元素比对才发现。已修（改成 `` `.lvl-*` 与 `.dot-*` ``），
   并加了 `t_css_comment_audit.py` 做全量审计。**教训：CSS 注释正文里绝不能出现 `*/`。**
2. **`mw_ume_topology.html` 的 `applyTheme()` 漏了 `refreshPalette()`**。首屏因为「先设
   `data-theme` 再读令牌」所以是对的，但运行时 `postMessage` 切主题时 `PALETTE`/`LVL_COLOR`
   不刷新，页面会停在启动那一档。已补（`mw_real_time.html` 本来就有）。
3. **地图站点标记的内联色不跟随主题**。标记色来自 `LVL_COLOR`，而标记是「建图时一次性生成」的，
   不重建就保留上一档颜色。已在 `applyTheme()` 里补 `renderGeoNodes()` 重建。

另外把「本该与主题无关、却被改成随主题切换」的地方改回固定令牌：

- `.geo-cluster` / `.leaflet-control-attribution`（含 Leaflet 缩放控件的 SVG 图标、
  版权条里的 Leaflet logo —— 它们靠 `currentColor` 继承 `<a>` 的颜色）原本是硬编码
  `#19c3ff` / `#9fb3c8`，迁移时写成了 `var(--accent)` / `var(--muted)`，于是浅色档跟着变。
  它们浮在地图瓦片上，本就该与页面深浅档无关 → 改回 `var(--vmax-cyan)` / `var(--vmax-text-muted)`。
- `.kpi .k-why` 的底原本是 `rgba(255,255,255,.08)`（hover `rgba(25,195,255,.18)`），
  同样与主题无关 → 浅色档用 `--vmax-fill-1/2` 覆盖还原原值。
- `cxo_dashboard.html` 的激活态标签文字：深色档用 `var(--vmax-bg)`，浅色档原本是 `#04222f`，
  加一个 `--tab-on-text` 变量（浅色档定义、深色档走 fallback）即可做到浅色档**逐元素零差异**。
- `legacy-vmax-theme.css` 末尾加 `html[data-theme="light"]{--surface-bg:var(--panel);
  --surface-shadow:none}` 兜底：`:root` 里的 `--surface-bg` 是 vmax **深色**卡片渐变，
  而 legacy 页的浅色极性有两种写法（有的用 `html[data-theme="light"]`，有的把浅色放 `:root`、
  深色才走 `[data-theme="dark"]`，如 alarm-management），某页漏写覆盖就会在浅色档拿到深色渐变。
  各页自己的 light 块特异性相同且文档顺序在后，仍可覆盖 —— 「默认安全，需要时才特化」。

**残留（已逐条确认，非缺陷）**：mw 两页浅色档仍有少量**同族换色**，全部落在白名单里：
地图浮层的旧青 `#19c3ff` → vmax 青 `#00d9ff`、浮层底 `rgba(8,26,40,.88)` → vmax panel
`rgba(8,18,44,.88)`、版权条 `rgba(0,0,0,.5)`/`#9fb3c8` → `rgba(2,5,12,.55)`/`#aebbd4`、
以及健康度等级色（原文件同一个等级有**三套**色值来源：CSS `.lvl-*` 走主题变量、
CSS `.d-tr.u-*` 硬编码、JS `LVL_COLOR` 硬编码 —— 本次统一到 `--vmax-lvl-*` 一档，
浅色档下后两者从原来的亮色变成浅色档色阶，白底上更可读）。
cxo_dashboard 与 alarm-management 两页做到**逐元素零差异**（仅多出新引的 `<link>` 本身）。

### 踩到的坑（都要记住）

1. **CRLF**：这些 legacy 页是**纯 CRLF**。Python 必须 `newline=None` 读（内存里统一成 `\n`
   才能匹配多行锚点）、`newline='\r\n'` 写回，否则多行锚点全部命中 0 次、且容易把行尾改坏。
2. **锚点断言**：批量替换脚本对每个锚点断言「命中且仅命中期望次数」，任一不符即整体失败、
   **不落盘**。这一条实际救过场：alarm-management 的代理第一版在深色块注释里写了
   `--chart-*/--map-*`，其中 `*/` **提前闭合了 CSS 注释**，把整个 `[data-theme="dark"]{…}`
   吞掉、深色静默失效（body 变对了但 `--text` 仍是浅色值）—— 断言把它抓了出来。
3. **Tailwind preflight 假阳性**：Tailwind 给 `*` 设 `border-color:#e5e7eb` 但**宽度为 0**，
   全量扫描 computed style 时会把 `<html>/<head>/<link>/<meta>` 这些不可见默认值报成
   「老色残留」。**边框色必须配合该边 `border-*-width > 0` 才算可见**。
4. **`networkidle` 不可用**：这些页有 5 分钟轮询/长连接，`wait_until="networkidle"` 可能永远
   不满足（alarm-management 实测 30s 超时）。改用 `domcontentloaded` + 固定等待。
5. **「有效页面底色」不能只看 `body`**：Tailwind 页 body 常常是透明的
   （`incident-overview` 实测 `rgba(0,0,0,0)`）。做法：视口打 9×5 网格，每个采样点从该点
   元素向上找到第一个不透明背景，取**众数**。判定用「body 底色 **或** 采样众数 == vmax 底色」，
   因为有的页 body 正确但被大量半透明面板覆盖（`ip_trace` 众数是 `rgba(21,61,176,.3)`）。
6. **注释里绝不能写 `*/`**（见坑 2；本轮自己又踩了一次，见「浅色档保真」第 1 条）。
   这个坑在**同一个项目里一天内出现两次**，务必用 `TMP/t_css_comment_audit.py` 全量审计。
   注意「星号简写」是重灾区：想写 `.lvl-*/.dot-*` 就会产生 `*/`，改成 `` `.lvl-*` 与 `.dot-*` ``。
7. **「浅色档没变」必须逐元素验证**，只比 body 底色/主文字会漏掉真 bug（本轮就漏了
   `--vmax-lvl-healthy` 被吞、`applyTheme` 漏 `refreshPalette`、地图标记色不跟随主题这三条）。
   工具：`TMP/t_legacy_light_elementdiff.py`（按字段多重集 + 同族换色白名单）。

### 两条只在「多跑几次」时才暴露的坑

1. **数据驱动的色值要整条补全白名单**。健康度 7 级色由 JS 写进 inline style，而地图上出现
   哪些站点状态是**数据驱动**的 —— 某一轮探针只抽到 healthy/critical，下一轮才抽到 moderate，
   于是白名单漏一档就会变成「随机失败」的假告警。教训：这类白名单要按**整条色阶**补。
2. **Leaflet 内部结构会造成元素数抖动**。`incident-overview` 同一版本两次跑元素数
   1601/1602 抖动，定位到是 `DIV.leaflet-tile-container.leaflet-zoom-animated` 在瓦片加载/
   缩放动画中被创建销毁（1 个 vs 2 个），属第三方地图内部行为。核对脚本必须排除
   Leaflet 内部 pane，但保留 `.leaflet-control-*`（缩放控件、版权条）—— 那些确实带颜色。
