## 修 Bug：eFlow 一键登录「报已登录但实际没登录」（根因：CDP 写 localStorage 的时序）

用户报：`http://localhost/myapp/?page=portalLogin` 点 eFlow Alarm System →
提示「Logged in; browser window stays open」，但页面上账号密码根本没进去。

### 复现（走真实 API，最有效）
`POST 127.0.0.1:7038/api/portals/login {"system":"eflow"}` + 轮询 `login/status` 把
`log` 全打出来 → 拿到 `state=failed`、`csrftoken 写入 localStorage：失败（接口可能 403）`、
页面文案 `This request is prohibited for cross-site access / Your session is error`。
**结论：直鉴权本身没问题（`_eflow_direct_auth` 手测能拿到 5 个 cookie + forgery_token），
坏在「种 cookie 后的 CSRF token 写入」。**

### 根因（2026-09-13 确诊）
`Chrome` 一启动 `DevToolsActivePort` 就出现，此时启动页还在 `about:blank`
（origin=`null` 的不透明源）。旧 `_cdp_set_eflow_cookies` 连上来立刻
`Runtime.evaluate("localStorage.setItem('csrftoken', ...)")` → **SecurityError**
→ csrftoken 没写进 localStorage → eFlow 前端所有请求缺 `forgery` 头 → 整页
"Your session is error. Please login again."。
旧的成功判定又太松（URL 判据恒真 + 「innerText 非空就 break」）→ 报出假的「已登录」。

### 修法（`portal_login_service.py`）
1. `_cdp_set_eflow_cookies`：**先等页面真正落到门户源**（轮询 `location.href` 的 netloc == host，
   25s×2 轮，超时则主动 `Page.navigate` 到门户入口），再种 cookie；
   csrftoken 写入回读校验 + 3 次重试；cookie 全失败直接抛错。
2. 新增 `PORTAL_READY_JS` / `_SESSION_ERR_RE`：正证据 = 正文 ≥120 字 + 无会话错误文案
   + 无可见 `input[type=password]`；**连续 2 次命中才算成功**（eFlow 主页刷新瞬间会只剩
   "My Favorites / No data." 的中间态，单次命中会误判）。
3. `_cdp_navigate_and_verify` 重写判定循环（45s）：失败信号=会话错误文案/被打回 `/login`
   或 `/api/oauth2`，连续 2 次命中即 failed。

5. 前端 `PortalLogin.tsx`：客户端模式下**直连门户（eFlow/RAIS）不再标 success**
   （原来卡片显示「已登录」但页面上什么都没填）→ 标 `need_manual` + 提示切「服务器」模式；
   `isLive` 排除客户端 need_manual。i18n 文案去掉 eFlow 专属措辞。

### 沙箱坑（新增）
- 脚本里 `urllib.request.urlopen("http://127.0.0.1:<cdp>")` 会被 `http_proxy` 劫持 → **502**；

  `Security.setIgnoreCertificateErrors`，否则停在 "Your connection is not private" 拦截页。

  仍有效，watchdog 10s 内拉回。

## 第二轮：用户「点击还是没有登录」→ 客户端模式自动改走服务器登录

用户反馈（10:21）：「点击还是没有登录」；随后补充**「不要使用代理的方式，会导致下级页面
无法正常打开的 / Failed to Query Active Alarm Columns and Default Templates」**、
**「eFlow Alarm System 这个不能代理，其他的可用」**，最后说「现在正常了，是因为我要选择
Server，然后点击」。

### 定位（关键：看日志里有没有 POST）
`log/backend_runtime_*.log` 在我修完之后**再无 `POST /api/portals/login`** → 用户点的是
**客户端模式**（前端默认 `client`）：直连门户直接 `window.open(https://10.100.20.8:28001/…)`，
不填表、不登录，旧代码还把它标成「已登录」。
→ 与用户第一条反馈的「Logged in 但没看到账号密码」完全吻合。

### 实测：eFlow 走 nginx 反代到底行不行
`TMP/t_proxy_login2.py` / `t_proxy_login3.py`（起干净 Chrome 打开
`http://localhost/api/oauth2/v1/authorize?…`，注入脚本确实自动填表并登录成功）：
- **能登录**：最终 URL `http://localhost/uportal/framework/default.html#/home`，`admin (Administrator)`；
- **但告警数据全是 0**：`All Alarms 0 / 0`、45s 不变，而 **HTTP 失败请求 = 0**
  （接口 200 但空数据 → 门户前端把根地址/实时通道写死到上游，反代下发不出去）。
- 与用户说的「Failed to Query Active Alarm Columns and Default Templates」一致
  → **eFlow 绝不能反代，只能服务器端直接鉴权**（RAIS 同理；其他门户反代正常）。

### 改法（让用户不必手动切「服务器」）
1. 后端 `portal_login_service.py` 新增 `local_addresses()` / `client_is_local(ip)`；
   `routers/portals.py::get_portals` 增加 `request: Request`，返回体多一个
   **`client_is_local`**（标记 `RCK_PORTALS_V3_LOCAL`）——按访问者 IP 判断他是不是就坐在
   my_app 服务器上（含 127.0.0.1/::1/本机网卡地址）。
2. 前端 `PortalLogin.tsx`：`handleLogin` 里 `localDirect = isDirect(p) && (clientIsLocal ||
   主机名是回环)` → 直连门户 + 本机访问者**直接走服务器端直接鉴权**（不再 window.open）；
   远程访问者仍打开上游登录页 + 提示切「服务器」。
3. 顺手补 `portal.loggingIn` i18n 键（STATE_TEXT.launching 引用它，原来漏了 → 卡片显示
   原始键名 "portal.loggingIn"）。

### 端到端验证（真实鼠标点击，`TMP/t_click_eflow2.py`）
用 CDP 打开 `http://localhost/myapp/?page=portalLogin`（全新 profile → 默认 client 模式），
`Input.dispatchMouseEvent` 发真实手势点 eFlow 卡片上的 Login：
- 点击后 **1.0s** 页面发出 `POST /api/portals/login`（= 自动走了服务器端鉴权）；
- 卡片：`Launching browser & logging in…` → `Live ｜ Logged in; browser window stays open`
  ｜ `已直接鉴权并进入 eFlow 主页 (…/#/home)｜首屏已渲染且无会话错误`；
- 弹出的 eFlow 窗口：`admin (Administrator)` + `All Alarms 6767 / 6767` 等真实数据 ✅
→ **用户现在「本浏览器」模式直接点一下就登录，不用再切 Server。**

### 沙箱/工具经验
- 真实点击用 `Input.dispatchMouseEvent`（`mouseMoved` + `mousePressed/Released`，
  记得带 `buttons:1/0`），再用 `Network.requestWillBeSent` 确认请求真的发出去了；
  判定不了时退回 JS `el.click()`（能触发 React onClick，但**不算用户手势**，window.open 会被拦）。
- 浏览器 locale 是英文时 Chrome 会**自动翻译页面**，导致卡片文案突然变英文
  （"I have been directly authenticated…"）→ 别误判成 i18n 出问题。
