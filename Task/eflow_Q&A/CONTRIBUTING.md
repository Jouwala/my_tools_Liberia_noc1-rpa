# 贡献规范

写一条知识库条目前，花 2 分钟看完这个。目标是**别人（包括 AI）查到时能直接用**。

---

## 一、什么值得写成一条

写之前先问：**这个问题会被问第二次吗？**

✅ 该写：
- 有人问过一次以上的问题
- 操作中有坑、有隐含前提（「必须先在 X 里配置，否则 Y 不生效」）
- 报错信息不直观，靠猜要很久
- 业务口径只有少数人知道（比如「挂起工单不算超时」）

❌ 不写：
- eflow 界面上点开就看得见的按钮说明
- 一次性的临时处理记录（放工单备注里）
- 未验证的猜测（要写就标 `状态: 待验证`）

---

## 二、写作步骤

1. 决定类型 → 从 `_templates/` 复制对应模板
2. 放到正确的分类目录（放错了比不写更糟，见下方目录对照）
3. 按模板填，**删掉模板里的提示文字**
4. 在 [INDEX.md](INDEX.md) 加一行索引
5. 若来自 BACKLOG，把 [99_待补充问题_BACKLOG.md](99_待补充问题_BACKLOG.md) 里对应项划掉并链到新条目

## 三、文件命名

```
<对象>_<动作或问题>.md
```

- 用**中文 + 下划线**，不要空格（空格在命令行里很麻烦）
- 名字要能猜出内容，避免「说明.md」「问题1.md」

✅ 好例子：
- `TT工单_状态流转与枚举值.md`
- `告警_实时告警不显示排查.md`
- `同步任务_eflow_tt字段映射.md`

❌ 坏例子：
- `新建 Microsoft Word 文档.md`
- `问题.md`
- `temp.md`

## 四、YAML front-matter 规范

每个条目开头必须有这一段（模板里已含）：

```yaml
---
标题: TT 工单有哪些状态，分别什么意思
分类: 00_操作篇_Operations/01_工单管理_TT_WO_CR_PM
标签: [TT, 工单状态, 枚举值]
状态: 已验证          # 已验证 / 待验证 / 已过时
适用对象: 运维        # 运维 / 开发 / 全部
最后更新: 2026-09-01
作者: 如意
来源: 实际操作确认    # 实际操作确认 / 代码读取 / 文档摘录 / 他人转述
---
```

### `状态` 字段是硬要求

| 值 | 含义 | AI 回答时的处理 |
|---|---|---|
| `已验证` | 本人实际操作/查库确认过 | 可直接作为答案 |
| `待验证` | 听说或推断，没验证 | **必须提示用户「此条未验证」** |
| `已过时` | 系统改版后失效，留档参考 | **不得作为答案**，仅供历史参考 |

### `来源` 字段决定可信度

优先级：**实际操作确认 > 代码读取 > 文档摘录 > 他人转述**

> ⚠️ 本项目铁律：**不许凭印象写**。
> 「这个函数会上传 FTP」这类声明，必须 grep 到真实调用点才能写。
> 由常量定义推断出来的结论，已经翻车两次了。

## 五、正文写作要求

### 1. 结论先行

第一句就给答案，别铺垫。运维同事是带着问题来找的。

```markdown
❌ eFlow 的 TT 工单系统是一个用于管理故障工单的系统，它的状态流转机制比较复杂，
   涉及多个环节和角色，下面我们来详细介绍一下……

✅ TT 工单共 6 种状态：Open / In Progress / Pending / Resolved / Closed / Cancelled。
   其中 **Pending（挂起）期间不计入超时考核**。
```

### 2. 给可复制的东西

- 命令、SQL、参数 → 用代码块，确保能直接复制运行
- 界面操作 → 写清「哪个菜单 → 哪个按钮」，不要只说「在设置里配置」
- 报错 → 原文照抄，不要转述

### 3. 标注不确定性

不确定的地方直接写「待确认」，不要含糊带过：

```markdown
> ⚠️ 待确认：Pending 是否计入 SLA，需找 XX 核对。
```

### 4. 截图

图片放同目录，用相对路径引用：

```markdown
![TT状态流转](./images/TT状态流转.png)
```

## 六、更新已有条目

改别人的条目时：
- 更新 `最后更新` 和 `作者`
- 若内容变化大，在文末加「变更记录」：

```markdown
## 变更记录
- 2026-09-01 如意 初稿
- 2026-09-15 张三 补充 Pending 不计超时的规则（经 XX 确认）
```

## 七、最小可行条目

没时间写完整？**写 3 行也比不写强**：

```markdown
---
标题: XXX 报错怎么办
状态: 已验证
最后更新: 2026-09-01
作者: 如意
---

## 现象
XXX

## 解法
重启 YYY 服务即可。

## 备注
根因没查，先记解法。
```

后面有人补根因时再扩写。**空白文档才是知识库最大的敌人。**
