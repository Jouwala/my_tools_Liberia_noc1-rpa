# OLBR 离线副本 · 部署说明

> 配套文件：`scripts/build_olbr_portable.ps1`（打包）、`scripts/portable/manifest.json`（保留清单真相源）。
> 本文面向拿到副本、要在另一台机器上把它跑起来的人；打包侧操作在主仓库做。

## 一、这个副本是什么

把主仓库 `D:\01_RPA` 里**四样东西**连同运行时，打包成一个可换机、可离线运行的目录（默认 `D:\01_olbr_portal`）：

| 内容 | 说明 |
| --- | --- |
| 统一门户 | React 19 + Vite，生产态由 Express（`server/index.ts`，9267）服务；静态壳由 nginx 直接 alias |
| my_app | FastAPI 后端（7038）+ vite preview 前端（7090）+ `Task/_fe_dist` 构建产物 |
| WhatsApp bot / 问答助手挂件 | `Task/whatsapp-kb-bot`，问答服务 9269 由后端按需拉起 |
| 运行时 | `runtime/python312`、`runtime/node`、`runtime/postgresql16`、`nginx-1.28.0`（含地图瓦片） |

**刻意不带**：生产 `.env`（含明文口令）、门户 `auth-data/`（加盐密码哈希）、bot 的 WhatsApp 登录态与私钥、FineBI / eFlow 等内网上游、`app.db`（2.58G，PG 模式下不读）、Chrome、开机自启计划任务。

> ⚠ **证书安全**：`nginx-1.28.0/certs/portal.key` 是自签证书私钥，随副本分发等于交出这把钥匙。它只用于让 `https://localhost/` 在本机可用；副本交给别人之前，请在目标机重新生成一对自签证书并替换这两个文件。

## 二、打包（在源机器执行）

```powershell
cd /d D:\01_RPA
REM 1) 先干跑，看清会动哪些目录
powershell -NoProfile -File scripts\build_olbr_portable.ps1 -Stage all -DryRun

REM 2) 正式打包（CopyRoot 必须已存在；quarantine 会把副本里的无关目录移入 _quarantine_<日期>\，可逆）
powershell -NoProfile -File scripts\build_olbr_portable.ps1 -Stage all

REM 3) 数据快照：单独跑，会读生产口令，务必先 DryRun
powershell -NoProfile -File scripts\portable\bundle_data.ps1 -DryRun
powershell -NoProfile -File scripts\portable\bundle_data.ps1 -Stage all
```

阶段可单独重跑：`quarantine` / `source` / `prune` / `nodemodules` / `runtimes` / `nginx` / `config`。

`prune` 清掉旧全量拷贝残留的 AI 元数据、缓存与日志（`source` 用 `robocopy /E` 只增不删，排除规则挡不住已经躺在副本里的旧文件）；规则在 `scripts\portable\manifest.json` 的 `prune` 段，幂等、支持 `-DryRun`，跳过 `node_modules`/`runtime` 并保护 `.env` 等运行时配置。
日志落在主仓库 `TMP\_build_portable_<阶段>_<时间戳>.log` 与 `TMP\_rc_*.log`。

`config` 阶段会铺这些东西：

| 目标位置 | 文件 |
| --- | --- |
| 副本根 | `start.bat`、`stop.bat`、`write_nginx_conf.ps1`、`nginx.conf.template`、`部署说明.md`、`.env`（首次） |
| 副本 `nginx-1.28.0\html\index.html` | 由 `nginx_index.html` 生成的服务导航页 |
| 副本 `scripts\` | `start_all.ps1`、`stop_all.ps1`、`bundle_data.ps1`、`env_template.txt` |
| 副本 `my_portal\` | 9 个可双击 `.bat` + `status.ps1` + `make_desktop_shortcuts.ps1` + `README.txt` |

## 三、首次运行（在目标机器执行）

1. **改端口（仅当与生产同机试跑时）**：编辑副本根 `.env`，把 `NGINX_HTTP_PORT` / `MY_APP_BE_PORT` / `MY_APP_FE_PORT` / `PORTAL_PORT` / `PGPORT` 全部改到空闲端口。`write_nginx_conf.ps1` 会按 `.env` 自动展开 nginx 配置，不要手改 `nginx.conf`。
2. **填密钥**：`.env` 里 `OPENWEBUI_API_KEY` / `CHAT_API_KEY` / `QA_*` 模型相关项默认留空或回环占位，按目标机实际模型服务填写。**不要把真实值写回版本库。**
3. **启动**：双击根目录 `start.bat`（等价 `powershell -NoProfile -File scripts\start_all.ps1`）。
4. **停止**：双击根目录 `stop.bat`。它只按 `TMP\portable-*.pid` 停本副本的进程，**不会碰生产实例**。

`start_all.ps1` 的顺序：便携 PG → 生成 nginx 配置（含 `nginx -t` 校验）→ my_app 后端 → my_app 前端 → 门户（+ 可选 9268/WA bot）→ nginx。每一步都查端口，已被外部进程占用就跳过并告警，绝不抢端口、绝不杀进程。

### 快捷入口：`my_portal\`

副本根 `my_portal\` 是一排可双击的入口，等价于源机桌面那个同名文件夹，但**自带、可移植**：所有 `.bat` 只用 `%~dp0` 推路径，整体换盘符或拷到别的机器仍然有效。根目录的 `start.bat` / `stop.bat` 依旧是一键总入口，这里只是把它拆成更好点的按钮。

| 入口 | 作用 |
| --- | --- |
| `0-status.bat` | 只读检查各端口与入口 URL；`LISTEN` 不代表由本副本占用（源机可能跑着生产），另列 `TMP\portable-*.pid` 佐证 |
| `1-start-all.bat` / `2-stop-all.bat` | 等同根目录 `start.bat` / `stop.bat` |
| `3-start-dryrun.bat` / `4-stop-dryrun.bat` | 预演启停计划，不启动、不停止任何进程 |
| `5-nginx-check.bat` | 按 `.env` 重新生成 `nginx.conf` 并做 `nginx -t` 校验 |
| `6-open-home.bat` | 打开 `https://localhost/` 导航页（按 `.env` 的 `NGINX_HTTPS_PORT`） |
| `7-open-logs.bat` | 打开 `TMP\` 日志目录 |
| `8-install-desktop-shortcuts.bat` | 在**目标机**桌面生成真正的 `.lnk` |

**不要**把源机桌面 `my_portal\` 里的 `.lnk` 拷进来：那些快捷方式写死 `D:\01_RPA`，且 `my_portal_ctl.ps1` 拉起的是生产实例（worker 组、watchdog、计划任务、WhatsApp 登录态），与本副本「禁调度器、按 pid 文件托管」的安全边界直接冲突。`8-install-...` 是运行时按 `$PSScriptRoot` 现算绝对路径生成，默认写到桌面 `my_portal_portable\`，**不会覆盖**已有的生产版 `my_portal\`；确需替换才显式加 `-FolderName my_portal -Force`。副本移动后重跑一次即可。

> 所有 `.bat` 必须保持纯 ASCII + CRLF，两个 `.ps1` 为 UTF-8 带 BOM（PowerShell 5.1 要求）。若副本路径含非 ASCII 字符，生成的 `.lnk` 可能不可靠，此时直接双击 `my_portal\` 里的 `.bat` 即可。

## 四、端口一览（默认值）

| 端口 | 服务 | 绑定 |
| --- | --- | --- |
| 80 | nginx HTTP 入口 | 0.0.0.0 |
| 443 | nginx HTTPS 入口（同一份 location 清单双监听；自签证书，浏览器会提示不信任，属预期） | 0.0.0.0 |
| 7090 | my_app 前端 vite preview | 127.0.0.1 |
| 7038 | my_app 后端 FastAPI | 127.0.0.1 |
| 9267 | 统一门户 Express | 127.0.0.1 |
| 9268 | WhatsApp 分析服务（`START_WA_ANALYSIS=1` 才起） | 127.0.0.1 |
| 9269 | 问答助手（首次提问时由后端 `portal_qa_ctl.py` 按需拉起） | 127.0.0.1 |
| 55432 | 便携 PostgreSQL | 127.0.0.1 |

入口（80 / 443 双监听，HTTPS 用自签证书，浏览器提示不信任属预期）：

- `https://localhost/` 服务导航页 —— 首页只列三张卡：`myapp` / `uniplam` / `olbrportal`
- `https://localhost/myapp/` Data Insight MVP
- `https://localhost/uniplam/` 统一门户
- `https://localhost/v3/olbrportal/` 当前版 OLBR 看板（带问答助手挂件）

把 `https` 换成 `http` 走 80 同样可用。团队门户与历史版本的 nginx 路由仍保留，只是首页不再列卡片，需要时直接输 URL 即可；`MsPortal` 静态资产也仍随包提供，供 OLBR 看板页加载。

## 五、安全边界（不要突破）

- `MY_APP_DISABLE_SCHEDULER=1` 由 `start_all.ps1` **强制**设置，不允许 `.env` 改回 0：否则采集任务会连生产上游，并可能重复投递 WhatsApp / 邮件告警。
- 副本不设 `MY_APP_TASK_QUEUE`，不起 `backend_watchdog` / worker 组 / 计划任务，避免自动复活与重复执行。
- 便携 PG 用 `trust` 认证且只绑回环；`DATABASE_URL` 里没有口令，`backend\.env` 首次生成时也只写本地回环连接串。
- `START_WA_BOT` 默认 0。改成 1 会用副本里的登录态接管 WhatsApp 会话，**必须先在目标机重新扫码**，否则等于冒用他人会话。
- 门户登录数据在 `runtime\portal-auth-data`（首次启动自建），是否随包分发由交付方自行决定。

## 六、排障速查

| 现象 | 先查 |
| --- | --- |
| nginx 起不来 / `[emerg] unknown directive` | `write_nginx_conf.ps1` 写的是 UTF-8 **无 BOM**；手工编辑 `nginx.conf` 时别用会加 BOM 的编辑器。日志在 `nginx-1.28.0\logs\error.log` |
| `/myapp/` 白屏 | `FE_DIST_OUT` 是否指向副本 `Task\_fe_dist`（`start_all.ps1` 自动填）；看 `TMP\portable-frontend.err` |
| `/uniplam/` 404 | 门户 `dist/` 是否随包带来；看 `TMP\portable-portal.err` |
| 后端起不来 | `TMP\portable-backend.err`；DB 相关先看 `DATABASE_URL` 与 `MY_APP_DB_MODE=pg`，再看便携 PG 是否在 55432 监听 |
| 数据库是空的 | 没跑 `bundle_data.ps1`；或只跑了 `-Stage dump`，补跑 `-Stage restore` |
| 问答助手一直转圈 | 默认 `QA_OWU_BASE` / `OLLAMA_URL` 是回环占位，目标机没有模型服务就会快速失败而不是白等；按实际服务改 `.env` |
| 端口被占用 | `start_all.ps1` 会打印 `[WARN]` 并跳过；改 `.env` 端口后重启即可，**不要**去杀占用端口的进程 |
| 停止后服务还在 | 确认跑的是副本根的 `stop.bat`；`TMP\portable-*.pid` 记录的是「pid + 进程名 + 启动时间」，pid 被复用时脚本宁可跳过也不误杀 |

## 七、已知边界

- 副本只保留源码与静态产物，`Task/_fe_dist`（约 142MB）与门户 `dist/` 必须随包；前端源码改动后需重新 `npm run build` 并重新打包。
- 离线地图瓦片在 `nginx-1.28.0\html\tiles\`，缺失时地图页面会白，`/tiles/` 走 alias 直发。
- `write_nginx_conf.ps1` 每次启动按 `$PSScriptRoot` 重算 `{{ROOT}}`，所以副本整体换盘符 / 改目录名不用手改任何配置。


## 八、迁移已有部署（换目录 / 换机）

**换目录或换机时，`Task/my_app/db/app.db` 里的三张「本地权威表」必须单独搬一次**，
否则会出现「凭据全空 + 任务启停全丢」：

| 表 | 内容 | 写入方 | 丢了会怎样 |
| --- | --- | --- | --- |
| `credentials` | 设置页的账号/口令（20 组） | `backend/services/credential_store.py` | 所有任务报「拒绝以空密码登录」 |
| `task_schedule_config` | 任务启停 / cron（74 行） | `backend/services/task_runner.py` | 任务管理页禁用全丢，手动停掉的任务重新开跑 |
| `email_recipients` | 邮件收件人名单 | `backend/services/email_recipient_store.py` | 邮件任务没有收件人 |

**为什么它们不会自动跟过来**：这三张表由应用**固定写 SQLite**，PG 里那份只是镜像；
`backend/scripts/sync_pg_to_sqlite.py` 为避免把本地数据 DROP 掉，把它们列进 `SKIP_TABLES`；
而同步器按策略不搬 `db/` 目录。所以「从 PG 重建 app.db」的部署路径**天生带不出它们**，
且不会有任何一步报错 —— 2026-11-11 的迁移事故（16 个任务同时报空密码）就是这么来的。

迁移步骤（在能同时看到旧/新两份 `app.db` 的机器上执行一次）：

```powershell
# 1) 先核对：目标为空而源非空时，退出码 2 并列出缺哪张表
python scripts\local_authority_tools.py check `
  --source <旧部署>\Task\my_app\db\app.db `
  --target <新副本>\Task\my_app\db\app.db

# 2) 正式迁移（先把目标表现状备份到新副本的 TMP\，事务内替换，逐行哈希校验）
python scripts\local_authority_tools.py migrate `
  --source <旧部署>\Task\my_app\db\app.db `
  --target <新副本>\Task\my_app\db\app.db

# 3) 复跑 check，必须退出码 0
```

`deploy_to_copy.ps1` 的 Step 1.5 会自动跑第 1 步：缺数据时**直接失败**并打印上面的 migrate
命令，不让「静默丢凭据」混进线上。全新部署（没有旧 `app.db` 可迁移）用
`-SkipLocalAuthorityCheck` 跳过，再按设置页逐组填。

> `TMP\_bak_local_authority_*.json` 含明文口令，只留在本机、不入库、不随便携包分发；
> 迁移完成后可自行删除。
