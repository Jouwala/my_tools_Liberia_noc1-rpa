# 执行效率与编排规范（高成功率、不空转）

> 背景（2026-11-11，会话存档实测）：「迁移RPA任务凭据缺失排查」会话全程 50 分钟，
> 其中 **46% 是主控在等验收队友**（11 次等待、大多等满超时），28% 是 104 步的模型生成
> （平均约 8 秒/步），工具实际执行只占 23%。等待的根因：队友任务书写了「代表性任务实跑」
> 却没有上限，实际触发多个生产任务（5 分钟 / 6.5 分钟 / 一个跑 18 分钟被 kill），
> 占用调度 worker，主控不得不显式发消息叫停。其它实测浪费：交互式 psql 密码提示挂起 141 秒、
> 全库哈希扫描两个 1.5GB SQLite 耗时 378 秒（后来沉淀的三表定向检查工具只要 1.8 秒）、
> 递归遍历目录找一个文件 71 秒、`Start-Sleep 60` 轮询、等待期间对同一 API 重复轮询七八次。
> 本文件把这些教训固化为编排纪律，适用于所有 agent 工具（Claude Code / Qoder / Cursor / DSH…）。
>
> 与其它规则的分工：**收尾标准与自检命令以 AGENTS.md 第五节为唯一真源**，本文件不重复；
> PowerShell 命令写法细则见 `shell_safe.md`；本文件只管「怎么组织执行才不空转」。

## 1. 计划与并行
- 动手前先读 AGENTS.md、相关子系统的 `docs/manual/`、`TODO.md`、`.agent-work/tasks/` 里的既有结论，不重新发现已记录的事实。
- 先分析依赖再分配：独立任务并行，有依赖严格串行。同一阶段的相关检查合并成一次调用；相互独立的调用放在同一批并行发出，减少总步数（每步都有固定的模型生成开销）。
- 诊断类任务优先单 agent + 并行工具调用；只有能独立交付的大块才开队友，禁止无意义创建（每个队友都是独立上下文，有自己的成本）。

## 2. 命令纪律
- 跑之前先估成本：全库扫描、整树递归、网络盘遍历是分钟级操作。先窄化再执行——指定表、指定目录、用 glob 代替 `-Recurse`。
- 禁止交互式命令（密码提示、确认提示）。凭据用环境变量/参数显式传入；传不了就换只读路径，不要让命令挂起等输入。
- 长命令放后台执行（DSH：`run_in_background` + `job_output`；Claude Code：Bash 后台任务），不阻塞主线；禁止 `Start-Sleep` 轮询。
- 禁止重复执行已成功且输入未变的检查；代码改动后只重跑受影响的检查（收尾自检按 AGENTS.md 第五节执行，不受本条豁免）。

## 3. 队友与等待
- 任务书必须写明：范围、输入、输出、**验收上限（测什么、最多测几个）与收尾条件**。没有上限的「验收」是最大的空转来源（见上方背景）。
- 启动队友后先做其它独立工作；等待时不要重复查队友正在查的同一状态。
- 靠完成通知和消息收集结果；不频繁轮询成员列表；多个短等待合并为一个长等待，不反复等待已知不会产生新消息的事件。

## 4. 验收与风险成比例
- 优先只读证据：日志、API 状态、DB 对比、连接测试。
- 实跑生产任务需明确授权，且限于代表性样本（默认 ≤2 个）；带外部副作用的任务（发信/发消息/投递）尤其谨慎。达到验收标准立即收尾，不加测。
- 不允许跳过必要验证，也不允许无上限追加验证——两者都违规。

## 5. 失败恢复
- 区分临时故障 / 逻辑错误 / 工具错误 / 业务验证错误；临时故障最多自动重试 2 次。
- 重试前先确认上一次执行是否已产生实际效果（幂等性要求见 AGENTS.md 第三节第 5 条）；已完成的任务不因其它任务失败而重跑。

## 6. 收尾与汇报
- 按 AGENTS.md 第五节跑 `agent-done-check`（改过前端/后端用 `--full`），贴出命令与输出。
- 汇报：完成/失败项、改动文件、验收证据、未验证项及原因、未解决问题。
- 不汇报无法内省的指标（实际耗时、工具调用次数、重试次数）——运行时不提供这些数字，写进汇报只会诱导编造；确有需要时由人解析会话存档获得。
- 禁止把「未验证」写成「通过」。
