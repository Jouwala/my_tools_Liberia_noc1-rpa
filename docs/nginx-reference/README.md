# nginx 配置参考副本

> 建立日期：2026-10-03　|　来源：`D:\01_RPA\nginx-1.28.0\conf\`

## 这里是什么

本目录存放**生产 nginx 配置的文本副本**，供新机器 clone 仓库后复原网关配置使用。

生效文件（**不是**本目录）：

| 机器 | 生效路径 |
| --- | --- |
| 本机 MSNOC1（.20） | `D:\01_RPA\nginx-1.28.0\conf\nginx.conf` ← 改这个 |
| .19 那台 | `\\192.168.100.19\e\01_RPA\nginx-1.28.0\conf\nginx.conf` |

## 为什么需要这份副本

`nginx-1.28.0\` 整个目录被根 `.gitignore:264` 忽略，理由是它是**可重新下载的第三方发行包**（79MB，`nginx.exe` + 一堆 `.pl` / `docs`）。这个判断本身没错 —— 但**发行包能重下，配置不能**：上面那份 `nginx.conf` 是 32367 字节、200 余行、本项目逐步积累的生产资产，**此前没有任何入库副本**。

结果是：新机器 clone 之后照着 `AGENTS.md` 也搭不出网关，表现就是「页面打不开」，且**现象隐蔽** —— 少一条 `location` 只会在某个 URL 上 404，不容易联想到是配置缺失。

**上传的是几十 KB 的文本，不是 79MB 的二进制包。** 这不违反「不上传发行包」的原则。

## 文件清单

| 文件 | 源大小 | 内容 |
| --- | --- | --- |
| `nginx.conf.txt` | 32367 B | 主配置：全部 location、反代、静态壳 alias、瓦片、B2/B5 安全整改 |
| `portal_ports.conf.txt` | 11700 B | 8081~8088 六个门户分站的端口反代 |
| `portal_eflow_common.conf.txt` | 3372 B | 门户 eFlow 反代公共片段（Cookie 域改写、摘 HSTS、sub_filter） |

扩展名用 `.txt` 而非 `.conf`：避免被 nginx 的 `include` 通配或构建工具误加载，也避免与仓库既有的 `*.bak*` 快照规则混淆。

## ⚠️ 已知问题：`portal_eflow_common.conf` 源文件本身是乱码

实测三份**源文件**的编码状态：

| 文件 | 字节数 | 可读中文字符 | 状态 |
| --- | --- | --- | --- |
| `nginx.conf` | 32367 | 2746 | ✅ 正常 UTF-8 |
| `portal_ports.conf` | 11700 | 439 | ✅ 正常 UTF-8（曾被误判为 GBK） |
| `portal_eflow_common.conf` | 3372 | **0** | ❌ **中文注释是 mojibake** |

`portal_eflow_common.conf` 的损坏方式是：**原始 UTF-8 字节先被按 CP1252 解读、再把解读结果存成 UTF-8**。磁盘上第 2 行的原始字节是：

```
35 20 C3 A9 E2 80 94 C2 A8 ...      →  解出来是 "é—¨æˆ·"
```

正确的中文是「门户反代公共片段」。修复方法（已对本目录副本执行）：

```
UTF-8 解码 → 按 CP1252 取回字节 → 再按 UTF-8 解码   →  「门户反代公共片段」
```

> 注意不能走 Latin-1（CP28591）：那会得到 `?--^?反代?...` 这种半残结果 —— 因为 `€` `—` 这类字符在 Latin-1 里没有映射，字节被吞掉了。**必须用 CP1252。**

**这是改动前就存在的问题，不是本次引入的**，也不影响 nginx 运行 —— 那些行全是注释，nginx 只读 `proxy_*` / `sub_filter` 指令。

本目录的 `portal_eflow_common.conf.txt` 是**已修复版**（155 个中文字全部可读），与生效源文件内容**不一致**（仅注释不同）。若要修生产源文件，把本副本的注释搬回去即可。

## 维护约定（重要）

改完生效配置、`nginx.exe -t` 通过并 reload 成功后，**必须把改动同步回本副本**。两份一起改，否则立刻分叉。

`AGENTS.md` 第四节 6b 条记录过一次因 `.19` / `.20` 两份 nginx 配置不一致而发生的线上事故 —— 加上本副本后，实际是**三份**需要同步。

## 重载的正确姿势

```powershell
cd D:\01_RPA\nginx-1.28.0
.\nginx.exe -t              # 改配置后先验证
.\nginx.exe -s reload
```

**必须先进到 nginx 自己的目录**：nginx 从自己所在目录的 `logs\nginx.pid` 读 master pid，在错误目录执行会把信号发给已死的 pid —— **命令不报错，只在日志里留一行 `OpenEvent(...) failed`**。2026-09-28 实测踩过：reload 打到 `91864`，真正的 master 未收到信号，nginx 随后停止服务直至人工重启。

> 桌面 `olbr_app\nginx-Stop.lnk` 的 `WorkingDirectory` 仍指向 Y 盘，它停的是 .19 那台，**对本机无效**。
