# 如意的运维工作台 — 交付说明

## 成品
- 文件：`D:\01_RPA\workbench\index.html`（单文件，37KB，双击即用）
- 定位：面向自动化运维 / RPA 工程师的个人作战台，不是通用待办清单

## 为什么是这 4 个模块
从历史会话和项目记忆里提炼出的高频动作：

| 模块 | 解决的真实问题 |
|---|---|
| 定时任务巡检 | my_app 里 20+ 个定时任务，靠脑子记谁该看了不现实 |
| 待办事项（P0/P1/P2） | 密码收口、atomic_write 接入、拉取窗口审计等长尾项容易沉底 |
| 踩坑速查 | 「绝不跑 stop.bat」「ROW_GROUPS 三处同步」这类铁律必须可检索 |
| 周报生成 | 前三个模块的数据自动汇总成文本，一键复制 |

## 关键设计
- **今天要处理**置顶：逾期项标红并显示拖了几天，每条带一键处理按钮；未完成项自动顺延，不会凭空消失
- 巡检「巡检正常」按钮 = 记录今日 + 状态置正常 + 按周期自动排下次日期
- 健康度圆环 + 近 7 天完成柱状图，均为手写内联 SVG
- 数据存 `localStorage`（key `wb_opsdesk_v1`），首屏就有导出 JSON / 导入恢复；导入无条数上限；清空需两次确认
- 累计 ≥30 条且 7 天未备份时，顶部弹温和提醒
- 零外部依赖：无 CDN、无框架、无字体外链、图标全部内联 SVG（已脚本校验通过）
- 移动端单列、按钮 ≥44px、输入框 16px、适配 iPhone 底部安全区

## 预置示例数据（含逾期项）
- 5 个巡检任务：ran_ume_main_kpi（逾期 + 关注）、sp_data_sync、eflow_active_alarm、ipran_ume_kpi、ms_sla_full（异常，DB 未注册）
- 5 条待办：含 1 条逾期的 P0「收口 7 处硬编码密码」
- 3 条踩坑：ROW_GROUPS 硬编码、远程库行数无界增长 + Begin Time 格式不一致、stop.bat 禁令

点页面底部「清空示例数据」可一键清掉，不影响自己新增的内容。
